## Decision

HOLD both managed providers. Neither existing path establishes a server-verifiable, distinct execution identity bound to the original durable launch before its first authority-bearing request. Nor does either establish a complete, immutable effective tool inventory. A scoped role ceiling is necessary but not sufficient for execution identity. No positive authenticated binding proof-of-concept is justified by current interfaces. Do not turn a mock observation into a production issuer. Preserve ordinary authorized, conflict-free manual use; do not enable the new scoped adapters or unattended replacement/resumption on this evidence.

## Required production contract (not authorized implementation)

Use the existing authenticated client, canonical Git project/account ledgers, and durable original-effect journal. No parallel authority registry or additional model credential. Define a host-produced, versioned execution binding with original launch ID/generation, attempt/assignment (or taskless activation) generation, account subject, device, project, actor, exact role/profile/config identity, provider and a stable authenticated execution context. The last field must come from a trusted transport/host facility with demonstrated binding semantics; a caller UUID, role, route suffix, MCP header/session ID without independently verified provenance, or prompt text is never sufficient.

1. Existing admission gate selects and persists the exact desired scope/config and original effect before dispatch. Require trusted provider-specific observation of complete effective inventory for this invocation, and an independently established server authorization ceiling. Neither may be copied from desired scope. Revalidate at transport entry, and reject unknown/drift before Send. Require that execution context is authenticated and linked by the existing trusted host before first authority call; pre-register only against a genuine execution identity, or gate all first requests pending verified association. Never accept first-to-claim actor/session as proof. If the provider cannot supply a pre-call binding or first-call gate, keep it unavailable.
2. On all authority-bearing ingress, resolve context from existing authenticated transport, not tool args. Constrain route, account, device, project, actor, role/tool ceiling, original generation and live canonical assignment/activation. Enforce both discovery and direct calls, including non-inbox first call, alternate ingress, generic endpoint, retry and promoted jobs. Route labels and role-specific schemas are not authorization. Carry verified context internally on the existing server-client channel; caller actor can be checked against it but cannot substitute. At transaction/activation/write boundary revalidate generation, ownership, STOP, exact source/claim and current authority; preserve exact already-applied receipt semantics without permitting new stale effects. Persist provenance needed for delayed completion and replay. A provider capable of obtaining the same broad account credential or accessing generic /mcp without authenticated distinction cannot be made safely narrow by a scoped URL. Do not globally block ordinary manual traffic just to manufacture this property; absent an enforceable distinction the provider remains held.
3. Browser: require supported provider/runtime evidence linking exact registered project and selected plugin, full effective tool inventory (including generic endpoint absence/enforced denial), and authenticated conversation/execution identity at MCP ingress before any authority action. UI selection or post-send route is diagnostic only. If a supported provider transport facility emerges, verify actual provenance and binding timing with isolated tests and separately authorized live validation. Do not rely on private ChatGPT interfaces. Closing launcher tab is not cancellation.
4. Codex: verify exact installed binary/version/cwd and effective configuration after managed, project, user, CLI and plugin layers; evaluate inherited allow/deny filters and all additional servers. Use non-secret inspection only, preserve current OAuth and process permissions. CLI list output can assist diagnostics, not certify exhaustive invocation inventory without demonstrated semantics and stable configuration through dispatch. A possible future trusted host-mediated per-process transport would need an independently proven, isolated existing-auth channel bound to the original invocation, inability to bypass via direct generic MCP, and no new credentials or permission widening; none is established here. Do not implement a proxy that simply forwards broad account credentials or asserts an unverified header.
5. For unavailable bindings, retain W6 scoped deny-all and W4/W8 conservative managed holds. Original verified no-send retry remains eligible. After acknowledged/uncertain send, negative actor activity, elapsed deadline, generic rejection, tab close, local process exit or optional launch ID do not authorize replacement. Require exact terminal evidence of no-start/no-further-authority or explicit authenticated Operator resolution tied to original verified termination; keep visible affected demand and capacity and allow unrelated eligible work. Manual conflict-free path remains distinct. Do not classify a valid cancellation request as termination.

Assert no activity/activation or effect for rejected requests, no fallback broad route, no duplicate original effect, and exact binding on successful current invocation. Use actual registered HTTP plus client transaction boundaries, not just a pure policy stub. Separately prove installed provider interface and effective observation semantics without secrets; live inference or config modification requires Operator authorization.
