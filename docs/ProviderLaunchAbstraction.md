## Contract

`ProviderLaunch.fs` separates original project/launch/effect identity and target generation from inference profile, MCP intent, resource configuration and transport observations. Named assignments and review claims are transitional targets; queue Work claims do not require an Agent identity. Profiles are chosen from already admitted, available candidates: hard profile/provider/MCP/capability requirements first, then soft tag matches, then the existing default, then deterministic ID order. Metered profiles are excluded in this slice, not used as implicit fallback. Selection grants no permissions and does not retry another provider after uncertainty.

The bootstrap is the exact verified renderer output (snapshot, template version/blob and prompt digest); providers receive the same prompt bytes. It is not a substitute for independently verifying the canonical origin or generation. Neither a vendor conversation URL, local process exit nor tab closure proves call-home or terminal Work. Reconciliation consumes exact identity/profile-bound transport facts and separately supplied verified canonical facts; duplicates/reordering are immaterial, contradictions hold, and foreign generations fail. The reducer is an observation projection, not a ledger writer, reservation release or replay permit.

Cache-friendly prompt assembly is owned by the canonical renderer (Worker 2, instruction consolidation spec v2). Keep its stable common/role prefix before volatile identity/assignment data. Both current adapters pass the exact complete renderer output without prepending provider metadata or changing ordering. The browser argument and Codex exec stdin are single user-prompt channels; moving stable text to a Codex developer-instructions override would change instruction authority, so no such split is performed. A future native interface may separate stable and dynamic sections only if the renderer explicitly supplies the boundary and the provider preserves authority and byte semantics. No cache-hit claim or padding; MCP argv ordering is deterministic.

## Adapters

- ChatGPT reuses the actual `BrowserBridge.runInNewTab` port and its current argument schema. No model override preserves current script defaults; an explicit profile uses a configured existing override alias. Acknowledgement does not require a URL in this contract, but the legacy script may conservatively report uncertainty until its own route requirement is met. Unsupported cancellation never closes a tab as a surrogate for canceling inference. The current script has no plugin-selector argument; this adapter accepts only an explicitly provisioned existing project/MCP context. The adapter's configuration flag is not verification or authority. Wrong/unprovisioned profile is a preflight rejection; actual focused plugin injection/selection and its proof require the separate browser/MCP profile wiring.
- Codex builds an argument-list command for an explicitly configured absolute executable and working directory, using `exec --json`, per-invocation `mcp_servers.<name>.url/enabled/required` overrides, optional model/effort, and exact canonical prompt via stdin. No shell, vendor history, credential acquisition, trust/approval override, secrets on argv, or new environment grants. It uses the existing bounded process runner through an injected host port. Local cancellation requests process-group cancellation; even a successful local exit or cancellation is not canonical termination. A JSONL `turn.started` event is only a transport acknowledgement. The installed npm wrapper and package manifest identify @openai/codex 0.144.4; public CLI source inspected at https://github.com/openai/codex/blob/main/codex-rs/exec/src/cli.rs documents noninteractive exec, JSONL and stdin. Exact installed-version option behavior and effective MCP configuration were not tested against the real CLI.

One adapter instance is scoped to one original effect. The in-process latch prevents duplicate dispatch inside that instance. On restart, a fresh adapter can observe only uncertainty; it must not enter Launch again for a possibly sent original effect. The existing durable journal, admission, generation and original-operation reconciliation remain the restart-safe fence; they are not replaced by the latch. Persist the selected profile, exact configuration identity and bootstrap with the original effect before entering any adapter.
