**Scope:** offline, two-clone, .NET 11 Release tests; **no Scheduler activation or live changes**.

## Verified contractual blockers

1. **The original WQ04 writer explicitly strips the lineage this binder requires.** `Client/Modules/WorkQueueCanonicalCasBinder.fs` (`publishFreshPractical`) prepares `CanonicalWorkOrigin` with `RoleId = ""`, `RoleVersion = 0`, `AccountCreditStatus = "NotReserved"`. For `TaskRequested` it additionally assigns empty `SourceRef` and `SourceCommit`. `Client/Modules/WorkQueueGitLedger.fs` (`publishCanonicalEvent`) enforces `origin.RoleId = "" && origin.RoleVersion = 0` inside the original Git CAS. The accepted diagnostic's `originGaps` in `Client/Modules/WorkCompositionQueueBinder.fs` correctly insists on positive role revision and approved source lineage. There is currently **no canonical original WQ04 stage that can pass this joint requirement**. Adding a fabricated role or choosing a role afterwards would be a new unsupported authority, not a fix.
2. **Original graph and queue transition writers publish separate heads.** `Client/Modules/WorkCompositionGitLedger.fs` (`executeVerifiedAcceptance` and the other graph transitions) writes `records/work-composition/graph.json` in its own `LedgerStore.transact`. `Client/Modules/WorkQueueGitLedger.fs` (`publishCanonicalEvent`, `change`, and `execute`) writes `records/work-queue/project.json` (and occasionally an origin) in another transaction, without reading the graph. `WorkCompositionAcceptanceAdapter.checkAt` verifies independent reviewed/integrated source proof, but is private to the graph writer. There is no shared internal validated candidate planner able to write both states with the original operation receipt and exact expected blob OIDs inside one `LedgerStore.transact` call. Sequencing two public writers would publish an observable graph/queue contradiction.
3. **The stage readiness algorithm does not encode composition acceptance.** `Server/WorkQueueContracts.fs` (`ready`, `orderAvailable`, `publishStage`, and `wakeBlockedStages`) considers the WQ02 stage State, Gate and WQ02 hard-stage dependencies; it has no proof-version linkage to `WorkComposition.currentAcceptance`. The graph can be Blocked on a cross-System/Feature prerequisite while the original WQ04 stage is Available at exactly the same verified head. Future `Reopen`, `Revise`, `Cancel` and graph-edge mutation can independently invalidate acceptance without atomically closing an already-published WQ02 stage. Merely making the acceptance operation atomic once does not fix subsequent revocation paths.
4. **The proof spans authority that must not be invented.** WQ07 account credit, WQ03 source-effect terminal/unknown reconciliation, original WQ04 source UUID/high-water, approved role revision and task-bound independent accepted review/integration must each remain authentic. WQ02 `Available` alone is not launch authorization. Neither a caller-supplied `Accept` flag nor a synthetic role/source record can bridge missing evidence. A multi-remote (account/source/project) Git operation is not globally atomic.

## Missing contract required for a future positive implementation

- Add a canonical typed graph-to-stage binding and proof-version edge from the original Work ID/generation to an exact composition unit/spec and current hard-prerequisite closure, with original WQ04/role/source lineage verified against one project Git snapshot; decide source-less planning stages separately rather than pretending they have source commits.
- Expose shared *internal* validated transition planners (graph acceptance/reopening/revision/cancellation, WQ02 stage publish/wake/hold/revoke, role/lineage and original event checks) that can produce both exact canonical file changes in **one** original project Git CAS and **one** immutable original operation receipt. Preserve existing queue invariant `Version = Receipts.Count`, original WQ02 ledger coverage, stable op UUID replay, and old-head losing-client reconciliation.
- Enforce the same gate for **all future graph-invalidating writes and WQ02 stage mutations**, plus every WQ08/WQ09/Work-native/scheduler read at its verified head. An already claimed stage or committed external push must retain its original hold and be reconciled; never silently reopen it on edge removal.
- Then demonstrate genuine two-clone accepted-review/integration source evidence, positive and adversarial negative stages with exact source-gated counts, same-head projection agreement, fake-only WQ11 vertical and cap-one WQ07; seek an independent frozen review and explicit GO/NO-GO before any cutover.

**Decision: NO-GO.** This branch does **not** replace the fail-closed binder or wire scheduler registration. It demonstrates a real missing original-contract dependency, not a successful replacement for Agents. Do not merge this evidence as if the positive WQ02/composition writer exists.
