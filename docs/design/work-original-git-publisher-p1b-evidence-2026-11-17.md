### Design and state boundaries

The accepted P0 \`Server/OriginalGitPublisherAdmission.fs\` remains unchanged. \`OriginalGitPublisherState.fs\` implements non-positive pure transitions. \`OriginalGitPublisherStore.fs\` is restricted to a directory containing exact disposable marker \`.jarvis-original-git-publisher-p1b\` and does not instantiate a second production Work database; a single-process per-path lane covers fixture remote mutation and barrier. It writes \`Prepared\` before invoking any external ref action; after a crash/restart any unfinished \`Prepared\` operation is durably \`Unknown\` and the gate enters \`RecoveryHold\`, never reissuing its UUID. It records Applied only after independently reading the expected new ref; errors at a potentially publishing boundary become unknown.

\`OriginalGitPublisherExecutor.fs\` obtains identity/inventory from an injected trusted fixture object, not from the \`OriginalGitPublisherCas\` caller, and performs the actual ref mutation under the same serialization lane as the durable barrier. A repeated exact UUID returns its immutable receipt; changed envelope or authenticated identity cannot republish. The gateway does not issue client-side \`mayPush\` permits. \`FencePending\` is committed before attempting remote-denial installation; incomplete history, unresolved effect, unsupported host admission, missing/extraneous inventory or divergent remote heads refuse a positive result. Positive \`FixtureBarrier\` outcomes in an in-memory deterministic fake remain A-only synthetic evidence. The bare-Git fixture explicitly returns \`UntrustedAuthority\` on remote enforcement verification, even with installed hooks, because it cannot prove direct-filesystem and orphaned in-flight exclusion. Remote publication after barrier is not attempted by this production-unregistered code.
