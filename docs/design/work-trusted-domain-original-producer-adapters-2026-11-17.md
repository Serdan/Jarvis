## 1. Decision and evidence grades

**HARD NO-GO:** No production implementation of the original remote Git writer admission/exclusive all-client barrier is present. Server/OriginalGitPublisherAdmission.fs:6-9,78-92 explicitly declares IOriginalGitPublisherAuthority a source-only interface, with no registered production authority. **B physical schema is not current ingress approval:** origin/main WorkSqliteAuthority.fs:14-49,157-189,589-655 has schema v1: eight kinds and strong local CAS, but admits arbitrary JSON-object BodyJson and optional syntactically valid source/review/integration SHAs. It has no independently authenticated original repository/ref, no private typed per-kind body boundary, and no proof against credential smuggling. This B v2 candidate must pass corrective frozen review before anyone relies even on its physical-schema gate; passing that gate would still **not** authenticate source ingress.

**C1/C2, E0/E1, G1 and F1 are narrower source proofs:** corrective C1 projection review eb29c792f15c4be78f82d1284d67a1b5 (accepted, frozen 3e795e008295f800a3010ca4bf67cb9a52be2977) establishes faithful offline source-shape equality and retained C2 receipt comparisons, not a production verifier (its CaptureVerifier is synthetic). E1a review 71d8e66d39084dc8a11ecc076188df62 and G1a correction review 7e6c0cbf3c4e49faa8776accf23a3c74 are default-off. F1 physical durability review 2b1adbcc41cc4ea6a3489fd51e096f18 is not the complete typed F/G gate. Original source strings, synthetic trusted booleans, or historical SQLite receipts must not be promoted to production permission.

For this plan distinguish: (1) **verified remote fact**, proved by an independently pinned authenticated project/account/repository/ref/commit source and immutable original operation/result/receipt; (2) **typed derived fact**, obtained from a complete verified source and exact graph/role/STOP/claim relation in one guarded local transaction; (3) **caller assertion**, including JSON, identity strings, “verified” booleans, synthetic gateway return values and request UUIDs. Only (1) may seed (2). Nothing in (3) creates a (1) witness by parsing or comparing its own text. A SQLite receipt proves an earlier local transaction, not renewed source authorization after new STOP, Recovery or changed approval.

## 4. Minimal composed ingress architecture

**Do not build a generic event bus or second authority.** Preserve WorkQueueProducers pure event/graph decisions, CanonicalSourceEvidence typed event/receipt verification, WorkLegacyImportPreflight C0 shape/coverage, WorkLegacyImportProjection full row equality, WorkSchedulerSqlite scheduling and WorkRecoverySqlite deterministic fences. Add a narrow internal trusted constructor and projector at their shared B persistence seam. Keep WorkSqliteAuthority.Commit as the single SQLite transaction/receipt/CAS writer, but make the raw command/BodyJson constructor inaccessible to activated Work RPC paths; it can remain temporarily available to hermetic legacy tests until an audited migration closes it.

Suggested **internal** API shape (names illustrative, not an instruction to copy code literally):

    type VerifiedOriginalScope = private {
        AccountId; ProjectId; LedgerId; Epoch; ApprovedDevice;
        RepositoryId; ApprovedFetch; ApprovedPush; Ref; PinnedCommit;
        SourceHead; SourceSequence; OriginalOperationId; RequestHash;
        OriginalResultHash; SourceReceipt; WriterBarrierEpoch }

    type VerifiedWorkEvent =
        | OriginalTaskPublication of verifiedOperation * approvedSpecVersion * role
        | OriginalStage of verifiedOrigin * typedStage * graphAndRole
        | OriginalFrozenReview of verifiedReview * immutableSource * decisionReceipt
        | OriginalIntegrationResult of verifiedIntegration * acceptedReview * effectReceipt
        | OriginalRole of verifiedRole * instructionDigest * subscriptions
        | OriginalCapacity of verifiedAccount * completeProjectSet
        | OriginalLaunch of verifiedReservation * scheduledVerifier
        | OriginalOneShotEffect of verifiedIntent * effectState
        | OriginalRecovery of verifiedRestore * capturedUncertainty

    module WorkSqliteDomainIngress =
        val construct : AuthenticatedSourceContext -> VerifiedWorkEvent -> Result<TypedDomainMutation, Gap>
        val commit : WorkSqliteAuthority -> TypedDomainMutation -> Result<WorkSqliteReceipt, Gap>

    module WorkDomainBackupProjection =
        val project : VerifiedFullDatabase -> Result<CanonicalJsonVNext, Gap>
        val restoreQuarantined : TrustedBackupRoot -> CanonicalJsonVNext -> EmptySqlite -> Result<RecoveryLockedDatabase, Gap>

All private witnesses must be created **inside authenticated original-Git source/remote authority**, with real project+account+device binding, verified Git refs/commit ancestry, graph/role/approval/STOP and operation receipt lineage. A string-bearing pseudo-DU constructed by an agent, JSON parser, a fake verifier or an ordinary host CLI is not a witness. The proposed VerifiedOriginalScope contains source-bearing fields only where one exists; planning task creation can carry an authenticated canonical operation with **SourceSha=None** until a real source lease exists. CredentialVerifier is a hash-only binding to scheduled reservation/project/work/role/STOP/permissions; BearerSecret and transient ManualGrant have no serializer or Work record variant. The server handler, not a caller's role name or external bool, determines allowed action.

**Atomicity and identity:** The one SQLite commit must guard the complete project/account scope and all related original row versions, stage/claim/STOP/role/graph/source SHA, decision and integration revisions, capacity version, original one-shot operation identity and account membership; it emits a unique command hash/UUID receipt and contiguous audit sequence. A stale operation UUID returns old immutable evidence, not active admission. Unknown or Prepared external-effect state may be read/retained but cannot become runnable, redispatched, erased or positively resolved by repair code. CAS failure must leave no partial project/role/stage/capacity write. Physical B schema v2 requires a separate reviewed migration for missing original canonical repository/ref/commit and verifier scope, and strict v1/v2 schema identity; reinterpreting an old row's SourceSha as repo/ref provenance is forbidden.

**Backups share the typed inverse, not a broad JSON fallback:** WorkSnapshotCodec.fs:11-38 (F0 v1) has a distinct logical flat-map representation including per-record Sequence that B does not store; never fabricate it. WorkSqliteBackup.fs:103-151 (F1 format v2) currently accepts narrow IDs (<=128) and only flat state/status/credentialVerifierSha256 bodies, while B permits <=256/noncontrol IDs and C/E/G write nested bodies. Widening safeBody to arbitrary JSON is unsafe. Keep its one-read-transaction physical capture (:278-316), deterministic checksums, restore staging/roundtrip and WorkBackupReplication async outbox, but project **every admitted per-kind typed version** and inverse exactly, preserving original field identities and complete account/receipt/audit history; refuse complete export if any legacy B row cannot be authenticated. A checksum does not authenticate backup Git source/ref/commit. Only a trusted pinned backup Git root and a successfully restored, **persistently boot-fenced** database may enter Recovery. A returned RequiresRecovery flag alone cannot stop a restarted server.

## 7. Cutover decision packet / exit criteria

1. **Original remote authority gate:** An independently verified production-bound implementation really enforces complete account+project+source ref inventory, source/operation ancestry, all-client remote exclusion (including stale and in-flight writes), durable barrier reinspection and recovery of Unknown outcomes. It must state exactly how old credentials/direct remote pushes are blocked. **Currently missing; responsible P1c/Worker 16 + original-C2 gateway.** If host rules/credential revocation need operator consent, bring an evidence-backed decision packet; this docs task cannot choose them.
