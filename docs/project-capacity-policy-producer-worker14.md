# Project capacity policy handoff

Base: accepted W21 same-CAS handoff abef95dc790ce6f95c51968e8cfb37203c431887. This component is default-off and unregistered; it does not provide production admission.

Policy is stored at records/project-capacity-policy/policy.json, schema 1, bound to project ID, ledger ID and epoch. It has a positive monotonic revision, positive total limit, and a nonempty map of explicit positive limits for named roles. An unlisted role is unknown and fails closed. Policy records are validated on every read, including exact fields and duplicate-key rejection.

`ProjectCapacityPolicy.readForRole binding snapshot expectedRevision role` returns the validated policy and blob ID or a failure. W21's future composed admission planner must call this within the same LedgerStore.transact callback as inventory validation and reservation, and recompute all of them on every retry. Bind the expected policy revision, role and all admission inputs into the transaction intent. A revision observed before the callback is only an expected version; stale or missing policy means HOLD. The W21 disposable reservation currently uses limits embedded in its fixture state; integrating this separate policy and making it authoritative requires changes outside this lease and independent review.

`update binding actor operation expectedRevision total roles` uses the existing LedgerStore transaction and client authentication. Revision zero creates only if absent; subsequent changes require the exact predecessor revision and replace it with the next revision. The intent binds the entire proposed policy and expected revision. A repeated identical operation returns the existing receipt; it does not indicate current policy remains unchanged. Reusing an operation ID for other inputs fails. No policy is installed or activated by this work.

W23 may project the policy only with the correct project, ledger, epoch, revision and source snapshot; a configured policy is not an inventory baseline, proof of complete writer coverage, an observation time, reservations, or an accounting of uncertain external effects. Unknown, incomplete, stale, or mismatched evidence remains HOLD. Neither policy read nor an idempotent transaction replay authorizes sending. Live configuration, trusted caller wiring, inventory provenance and freshness, reservation composition, external-effect recovery and complete writer coverage require separate work and approval.
