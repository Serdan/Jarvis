## Findings on registered paths

* Server/McpTools.fs:2829–2842 exposes ListJobs and GetJobResult as workspace:read tools. ListJobs builds project::worktree; Client/SignalR/Client.fs:313–348 parses the selector; dispatch 1493–1513 passes only ProjectTarget.projectId and the initiating transport actor to JobManager. This is a **logical-project and actor filter, not checkout filter**. JobManager.fs:221–236 and 548–563 apply it to process and exposed tool jobs; no worktree comparison. Tool summaries have WorkingDirectory=None; process WorkingDirectory is a path, not immutable checkout provenance. Omitted worktree does not mean main-only. Correct misleading tool parameter description before inventing a checkout filter. The local TUI no-actor view is not a remote observer capability.
* StartJob bypasses automatic promotion (SignalR/Client.fs:2037–2050), returns a process job ID. Slow RunCommand, TaskRead, BrowserRunInNewTab and other ordinary commands can return a ToolOperation handle (2110–2140) with PendingJob, initial state-change evidence pending. The handle can have no stable OperationId. JobManager.fs:688–697 looks in tool registry first then durable process registry. GetJobResult tool result carries nested immutable AgentCommandResponse, not an engineering exit status. Inspect inner Error, PendingJob, and typed result, including a StartJobResult if a wrapper legitimately returns one; never derive process ID by guessing from outer UUID. A RunCommand synchronous command result is itself not a StartJobResult. A completed transport wrapper is not necessarily a successful command or finished child. JobResult currently omits Kind; it must not be inferred from empty Events or null OperationId. See Common/Messages/AgentCommand.fs:33–49, 936–946, 1105–1113.
* At this baseline **both** registries enforce initiating actor on remote access. JobManager.fs:54–61 and 501–535; project mismatch fails closed. Earlier Interpreter access to particular process output is incident evidence, not proof of observer entitlement on this source or deployed versions. Do not impersonate an owner, widen GetJobResult or infer an ACL from workspace:read. ListJobs actor-private and omits unexposed quick operations. Errors currently distinguish a known wrong-owner tool from unknown ID; expiry tombstones keyed only by ID at 317, 339, 589–592 reveal an expiry classification without owner binding. New observer API must not inherit that oracle. Existing owner-facing behavior may be tightened separately after review.
* W14 retention seam: JobManager.Core uses BoundedProcess.DurableJobs original request/verified supervisor observation; terminal retention 100 jobs or 7 days, active cap 64; Unknown outcomes retain the checkout fence. Unknown (no verified live supervisor and no authoritative terminal receipt) is RecoveryUnknown, not Completed/Failed. Absent process receipt after pruning gives Unknown ID; do not infer absent job or success. ToolOperations memory limits: 32 running/queued, 8 workers, 100 terminal records or 30 minutes, bounded 200 expiry markers, expiry window 30 minutes, operation-dedup tombstones bounded independently. Restart loses registry and marker; a retained marker is not an authoritative effect outcome. Running operations not pruned. W14 owns durable process persistence; no second registry.
* W17 wake authority: Client/AutomationJobTerminalWake.fs terminalEvidence uses Durable.observe Terminal, matching request actor/project/job, completion time, status and receipt SHA256. Reconcile discovers canonical Challenge conditions owned by issuer, checks exact pending condition and original request re-read, resolves through ChallengeWorkflow.resolveJobTerminal with stable CAS operation ID. Startup, reconnect, registration and receipt publication are hints; neither ListJobs absence nor observer projection should trigger an independent wake. Terminal failure/cancel still satisfies "finished", not "succeeded". Generic remote Resolve cannot manufacture terminal proof. Preserve W17's single canonical resolution/requeue.
* BrowserRunInNewTab path SignalR/Client.fs:1186–1288 and beginAttributedLaunch/finishAttributedLaunch: attributed launches persist original intent and outcome under records/browser-launches/<launchId>/, with target agent, assignment snapshot, script source digest, later registration/outcome/reason/timestamp. Current launchId is generated INSIDE the command after promotion admission; pending ToolJobHandle has no launchId or guaranteed stable operationId, hence no exact handle-to-journal lookup after eviction. Only attributed launches journal; do not claim un-attributed manual browser execution is durable. Existing outcomeUnknown, notSubmitted, submission observation and persistence-unknown branches are distinct; agent activity, tab closure and assignment state cannot substitute for exact launch outcome or prove no send. Persist no additional private payload or browser URL in observer view. Native/scheduled launches retain their own existing authority, not this manual journal.

## Proposed minimal contract, no implementation authority in this task

Prefer extending canonical challenge/attempt dependency read surface over a general cross-agent job directory. New read-only operation takes project, exact challenge/condition locator (or equivalent reviewed canonical dependency capability), original typed handle, original destination device binding. Authenticate account and role/project access first; authorize only owner or explicitly authorized canonical dependency observer of that exact subject and current generation. Verify project/ledger/epoch, issuer/owner, condition binding and original typed request provenance before looking up status. No arbitrary ID cross-tenant oracle; foreign, unauthorized, malformed/unknown-without-binding collapse to one indistinguishable unavailable response. Do not expose command arguments, output, private errors, worktree paths, registration IDs, conversation URLs, credentials or actor names from other work. Existing owner GetJobResult and cancellation access unchanged. A read never resolves conditions, activates an agent, modifies last-seen or starts work.

Minimal proposed projection: schema=1, kind=Process|ToolOperation|AttributedLaunch, state=Pending|Terminal|Unknown|Unavailable, evidence=LiveSupervisor|DurableTerminalReceipt|OriginalToolCompletion|CanonicalOperationReceipt|LaunchJournal|None, outcome=Succeeded|Failed|Canceled|NotSubmitted|SubmissionObserved|Unknown (optional, kind-specific), original typed ID only if already authorized, optional receipt digest and observedAt. For ToolCompleted without typed inner outcome or with an unresolved inner process, report wrapper terminal only, not dependency terminal; attach an explicitly linked typed process reference only if original response contains it and same dependency authorization permits it. For RecoveryUnknown, missing receipt, eviction, restart, mismatched device or unverified link, report Unknown, never infer failure/no-send/success. Terminal process only from durable supervisor receipt (or already committed W17 condition evidence with exact matching identity); use exit code zero/nonzero internally to derive outcome, do not export raw output. Distinguish readiness from result success: canonical challenge status is authoritative for Ready. For ledger mutations use original operationId plus exact request identity and verified canonical operation receipt; a ToolCompleted wrapper alone does not establish a committed effect. No observer-side automatic reconciliation write.

Manual attributed launch correction: allocate a stable launch correlation before tool promotion; same ID is passed to existing begin/finish attributed launch journal, bound to canonical project, initiating actor, target and assignment snapshot. Expose original correlation to owner in pending handle, bind handle ID to intent atomically or deterministically derive a scoped correlation with collision and replay checks. On restart/expiry consult existing journal by original ID, not most recent launch, activity or guessed target. No extra outcome writer; no replay on lost response. Owner can use existing authorized journal path to recover tab mapping if policy allows; observer only compact outcome metadata. Pre-intent loss remains Unknown unless trusted no-send evidence. Unattributed commands remain explicitly nonrecoverable when no durable original identity. Design must be reviewed against existing launch journal/late-send holds (W8/W13); no weakening of manual launch authority or provider binding.
