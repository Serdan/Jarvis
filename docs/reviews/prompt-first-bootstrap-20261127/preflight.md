## Deterministic accounting and diagnostic contract (proposed)

Return a pure section manifest alongside composed prompt, never inject accounting into prompt. For each section (common, role, project, task, checkpoint/feedback/dependency, volatile; include explicit framing ownership) count UTF-8 bytes via strict encoding, UTF-16 code units (name unit; optionally Unicode scalar count), stable ordered section ID, version/digest provenance from canonical source. Sum exact serialized prompt section bytes including separators; independently count actual final JSON argument envelope with same encoder and route fields. SHA-256 for equality in memory/authorized provenance only; avoid exposing content-derived hashes for credentials/private text. Compare actual byte arrays to prior compatible prompt in memory or nonsecret section prefix manifests; longest common prefix bytes, with no mid-codepoint claim of characters; compare cross-agent common stable boundaries and same-role project prefix. Persist only section metrics, nonsecret schema/version IDs, aggregate counts and timestamps outside prompt, not text, snippets, full arguments, secrets, private IDs or credential hashes. A bounded in-memory comparison can produce exact prefix length; if prior bytes unavailable report unavailable or proven whole-section lower bound, never fabricate exact lengths or cache hits. Count duplicate layer identities / repeated safe section digests within one render, not generic repeated words; distinguish intentional precedence overlap. No provider tokenizer means bytes/chars only, not tokens. Provider-reported tokenizer/usage/cache metrics if available are separately labeled with provider, model and measurement source; never imply full hidden conversation context.

Initial proposed advisory thresholds, configurable per project/role/turn kind, based on the single fresh observed body baseline (not fleet norms): section warning at > baseline + max(25% of baseline, 1,024 bytes), e.g. Worker body 3,579, project 2,542, task 2,883, common workspace 2,895 bytes. Baseline is body-only, compare body-to-body, separately track framing; for checkpoint/feedback with no observed baseline collect cohort first, optional explicit configured budget, no invented zero baseline. Use 75% of each actual transport guard as global early warning (18,000 code units, 49,152 full args bytes, 98,304 serialized-string bytes); actual limits remain hard holds. The thresholds are engineering starting points to catch meaningful growth while avoiding tiny churn, not empirical percentiles or provider context limits. Establish reviewed fixed/versioned baseline from representative fresh/resumed/reviewer/Lead cohorts before general deployment; don't silently ratchet thresholds as bloat increases. Prefix regression warn if stable-scope same baseline and unexpected loss > max(10%, 256 bytes), distinguish intentional version change and volatile suffix; flag duplicate same layer identity immediately unless explicitly intentional. A budget violation stays advisory except an actual limit/invalid required input or authority fence.

Reuse existing operational health/diagnostic route (Program scheduling log, TUI/OperationalControl where suitable; not a new inbox or model analysis). Event fields: project/role scope, turn class, section enum, nonsecret version, metric unit, observed, baseline, delta, threshold, severity, reason, baseline version; no prompt, credentials, snippets, URLs, argument bodies or arbitrary exception interpolation. Emit once per (scope, class, section, metric, reason, baseline version, offending version) crossing, suppress repeat at same severity; emit escalation or material additional growth (same threshold increment), clear/rearm below 90% of threshold; bounded persistent counters/retention, aggregate trends, avoid per-agent spam. Exact dedupe key need not expose identities beyond authorized Operator reporting. Diagnostic failures do not change launch authority; hard limit checks stay synchronous and fail closed.
