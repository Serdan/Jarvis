## Authority boundary

The legacy branch claim CAS (ReviewWorkflow.fs:4568–4584) checks valid identity/IDs, expected version and exact Unclaimed status, then commits the claim. It does **not** itself require Reviewer role or prohibit self-claim. Green test proves both on disposable published reviews, including a registered actor without Reviewer role. This is an observed gap in this particular writer, not authorization advice or a mandate to change it here. A second claim using the original version fails, as do claims against withdrawn/decided records; stale pinned reads remain the old version while current reads expose the winner. Missing ref yields null HeadCommit in detail, while fetchReviewRef fails; malformed schema in a review record fails the queue rather than silently dropping it. Exact detail/document calls recover immutable source and summary blob/content, reject unknown review/unsafe path, and do not mutate ledger. The 1k fixture additionally checks owner working-turn, task and attempt unchanged; ledger commit identity establishes no subject state mutation either.

Independent acceptance checks in ReviewWorkflow.fs:1563–1588 and 2057–2084 enforce independence (ReviewerId differs from OwnerAgentId) with additional evidence checks. NativeSchedulerAccountReservation.fs:305–358 verifies Reviewer role and canonical claimed row, exact operation evidence and frozen ref. Those downstream predicates were source-inspected, not executed through native scheduler or integrated acceptance; the bulk projection must not replace them. Projection eligibility is advisory read-only and no authority is conferred by a row or cursor. Role absence, stale status/version, missing evidence and actor/subject distinction must be preserved at the applicable canonical write or execution boundary.

## Smallest proposed implementation (separate source lease required)

1. Retain branchReviewerQueue and internal consumers unchanged. Add one review-only pinned batch read in LedgerStore using existing readSelectedRecordsAt pattern (1717, 1825–1830); enumerate canonical tasks/<task>/reviews/<id>/review.json paths at one verified snapshot, batch-decode schema and check exact path identity, fail closed for corrupt canonical data. Do not fetch each review ref/document in list, add an index, or invent a general query framework. Read cost should be batch rather than one Git process per record; enumerating and counting all rows is still O(N).
2. New narrow ReviewWorkflow compact page producer for that snapshot: exclude subject-owned submissions, include foreign Claimed-by-subject first, then foreign Unclaimed; within each class order by existing (CreatedSequence, TaskId, ReviewId) using canonical ordinal keys. No role normalization/casefold; exact agent identifiers. Existing self-claimed anomalies remain inspectable in explicit full/legacy view and must not disappear from administrative recovery. Exclude terminal and other-claimed rows. This is an actionable discovery filter, not an independence or role grant. Preserve taskId/reviewId, current row version for claim CAS, owner, status, reviewer, source version, ref and source OID in compact rows; use exact existing detail/doc calls for additional metadata/evidence.
3. Propose default page maximum 32 and raw UTF-8 response budget below 32768 (measure escaping/wrapper separately; enforce actual serialized budget, not average length). Return snapshotCommit, reviews, availableCount (total actionable at snapshot), omittedCount (remaining after emitted page including previously traversed offset), nextCursor (null if exhausted). First-page count for 300-row fixture = 120, omitted = 88. Ensure at least one valid row fits, otherwise explicit bounded error; never truncate identity or evidence. Count only eligible rows, not terminal or own submissions. Stable ordering and page progression must not depend on map insertion or changing heads.
4. Reuse narrow existing cursor pattern in ReviewWorkflow.fs:1380–1411 (verifiedHistoricalSnapshot, project/ledger identity, bounded expiry and decoding), not a new pagination framework. Bind cursor to projectId, ledgerId, epoch, exact subject, projection/version, page limit, pinned snapshot commit, last key or validated offset, expiry (existing 30-min model). Verify reachability/snapshot and all fields on every continuation; validate position and reject malformed, expired, wrong-project/subject/version/cursor combinations, never silently switch to current head. Re-read same snapshot, deterministically resume after last key. Fresh request starts current snapshot. On claim, independently read/check live expected version and all current authority/evidence predicates; cursor is not capability or claim ticket.
5. Wire only this route through existing ReviewReadCommand/ReviewApi.read and MCP registration with shared source lease; preserve independent caller versus subject and existing auth, permissions and job promotion. Add optional cursor/page size and explicit full legacy selection using coordinated common protocol/client/server version compatibility. Do not turn old clients silently into incomplete consumers: first introduce versioned/opt-in compact behavior, audit all full-reader consumers, retain explicit legacy view, then switch default in coordinated release with tool metadata/prompt updates. Test actual registered direct and promoted terminal results, unchanged subject/caller state, role/source guards, page size and exact counts, tie order, multiple pages after concurrent claim/withdraw, cursor wrong subject/project/expiry, no duplicate/omission against pinned snapshot, and current claim CAS/evidence failure. Compact response never substitutes for exact review/detail/doc inspection.

The RED test intentionally defines an illustrative default of 32 records / <32KiB and first-page count fields; these are preflight proposal values, not a negotiated public protocol. Actual continuation, batch efficiency and coordinated rollout are not implemented or proven by this artifact. Green tests pin legacy baseline semantics and should remain green on the explicit legacy path; do not change their expectations to disguise a regression. No main/production edits.
