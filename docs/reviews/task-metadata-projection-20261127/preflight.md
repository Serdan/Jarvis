## Producer and integrity boundary at the baseline

- Server/McpTools.fs:2335–2337 GetTask is registered workspace:read, dispatching ReviewCommands.query with action GetTask.
- Client/SignalR/Client.fs:1426 invokes ReviewApi.read and the standard JSON serializer (755–778). Client/Modules/OrchestrationApi.fs:2497–2502 returns snapshotCommit, task, optional attempt, **current** specBlobOid and full specHtml.
- Client/Modules/ReviewWorkflow.fs:3691–3708 fetches one snapshot, requires task, calls LedgerStore.readAt for the current spec path and requires active attempt if present. It fails on missing spec path/object type; it does not revalidate authoring-time HTML safety. The existing read API getTaskAt (4064–4075) and getTask (4077–4082) omit the spec lookup entirely; using getTask alone would silently hide missing spec evidence and lose current spec OID.
- Client/Modules/LedgerStore.fs:887–895 private blobAt already uses git ls-tree at the supplied commit, requiring regular 100644 blob and well-formed OID. readAt (1594–1605) validates path and calls blobAt, then showBlob; no public body-free wrapper exists at this baseline. A tree entry proves identity/type, not object availability, size, UTF-8 or safe HTML. If missing/corrupt object evidence must remain immediate, the metadata path needs an exact-OID existence/type/size probe without materializing content; unexpected object kind, missing object and oversize must fail, not produce an apparently valid OID. An invalid body that still hashes to a regular readable blob is not discoverable from metadata alone; existing legacy GetTask does not validate HTML either. Explicit retrieval must preserve its current errors, and must not claim body validation it does not actually perform.
- ReviewWorkflow.getTaskSpecPage (1380–1440) establishes current path OID, reads canonical historical spec, then emits bounded UTF-8 pages; cursor includes task, ledger, snapshot, OID, offset, expiry. On continuation, verifiedHistoricalSnapshot checks canonical ancestry (LedgerStore 2127–2140). A new first page after revision selects the new current spec; that is not a request for the original assignment. getAssignment (2896–2923) provides immutable issuance with SpecBlobOid and validates task, attempt, generation, owner and acknowledgment. LedgerStore.readHistoricalTaskSpec (2091–2125) verifies historical membership at the task's spec path before loading exact blob. Do not expose arbitrary object lookup or synthesize cursor tokens as a client contract. Historical read still materializes full body internally; reducing explicit spec read IO is not this slice.

## Proposed minimal production wiring (not implemented)

1. Under a new explicitly coordinated lease, factor the safe path guard of readAt into an internal helper, and add an OID-only checked wrapper (e.g. tryBlobOidAt) using existing blobAt and pinned snapshot. Use git cat-file -t/-s or a single bounded batch-check for existence/type/size against that exact OID, preserving fail-closed missing/corrupt/type semantics without showBlob. No extra ledger fetch. Check that the existing raw Git error mapping cannot mask a missing object. Keep readAt and legacy full producer semantics intact.
2. Add getTaskMetadata in ReviewWorkflow: one LedgerStore.fetch; getTaskAt binding snapshot taskId; checked OID-only lookup at specPath taskId; missing path -> existing LedgerIntegrityError. Return snapshot, task, attempt, current spec OID. A pinned attempt remains the existing attempt record (generation and its distinct SpecBlobOid), never overwrite it with current OID. No writes or state transitions. Reuse getTaskAt rather than a parallel metadata reader. Avoid widening task/attempt schema.
3. Compatibility first: add distinct ReviewApi.read action GetTaskMetadata (same existing ReviewReadCommand shape and authorization), producing exactly snapshotCommit, task, attempt, specBlobOid; no specHtml/null placeholder. Register new read-only workspace:read tool via the existing query mapping and confirm discovery/scope/response limits; do not silently alter GetTask's existing contract in a mixed-version deployment. Inspect Server/McpTools read method and role-catalog filters, plus client command classifier before registering. Update internal metadata-only callers after explicit migration review. The ExpectedRed test targets the eventual *default* GetTask after coordinated migration; at the interim stage run equivalent assertions against GetTaskMetadata and retain old GetTask green controls. Do not declare the default contract green until intentionally switched.
4. Add an exact pinned spec page read using existing task read command generation (or an explicitly named action), not raw unscoped Git object ID. Refactor page implementation to select initial snapshot and authorized OID: generation >0 selects getAssignment's validated issuance, generation 0 retains current semantics. Bind continuation to task/ledger/snapshot/OID and selected generation or distinct action identity; reject cross-generation, cross-task or wrong-ledger cursor reuse, stale/unissued generation, and unavailable/malformed ancestry. Reuse existing readHistoricalTaskSpec and UTF-8 paging. A historical generation within the active attempt is the existing getAssignment scope; older replaced attempt retrieval is not silently promised by that API. Keep legacy GetSpecPage behavior for old clients.
5. Tests before any default migration: actual API and registered MCP routes for open/no-attempt and assigned task, 8 KiB and 512 KiB with escaped content; no body read and bounded metadata byte count, current-vs-pinned OID after revision, exact old issuance spec retrieval before/after head advance, stale/missing/invalid path/object/attempt, cross-task/generation rejection, scope denial and unchanged canonical head/state. Exercise old full GetTask and current paging unchanged. Test actual raw payload and outer transport size separately. Green production after new lease; independent review, integration and coordinated deployment are separate gates.
