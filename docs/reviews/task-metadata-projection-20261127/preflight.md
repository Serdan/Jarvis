## Producer and integrity boundary at the baseline

- Server/McpTools.fs:2335–2337 GetTask is registered workspace:read, dispatching ReviewCommands.query with action GetTask.
- Client/SignalR/Client.fs:1426 invokes ReviewApi.read and the standard JSON serializer (755–778). Client/Modules/OrchestrationApi.fs:2497–2502 returns snapshotCommit, task, optional attempt, **current** specBlobOid and full specHtml.
- Client/Modules/ReviewWorkflow.fs:3691–3708 fetches one snapshot, requires task, calls LedgerStore.readAt for the current spec path and requires active attempt if present. It fails on missing spec path/object type; it does not revalidate authoring-time HTML safety. The existing read API getTaskAt (4064–4075) and getTask (4077–4082) omit the spec lookup entirely; using getTask alone would silently hide missing spec evidence and lose current spec OID.
- Client/Modules/LedgerStore.fs:887–895 private blobAt already uses git ls-tree at the supplied commit, requiring regular 100644 blob and well-formed OID. readAt (1594–1605) validates path and calls blobAt, then showBlob; no public body-free wrapper exists at this baseline. A tree entry proves identity/type, not object availability, size, UTF-8 or safe HTML. If missing/corrupt object evidence must remain immediate, the metadata path needs an exact-OID existence/type/size probe without materializing content; unexpected object kind, missing object and oversize must fail, not produce an apparently valid OID. An invalid body that still hashes to a regular readable blob is not discoverable from metadata alone; existing legacy GetTask does not validate HTML either. Explicit retrieval must preserve its current errors, and must not claim body validation it does not actually perform.
- ReviewWorkflow.getTaskSpecPage (1380–1440) establishes current path OID, reads canonical historical spec, then emits bounded UTF-8 pages; cursor includes task, ledger, snapshot, OID, offset, expiry. On continuation, verifiedHistoricalSnapshot checks canonical ancestry (LedgerStore 2127–2140). A new first page after revision selects the new current spec; that is not a request for the original assignment. getAssignment (2896–2923) provides immutable issuance with SpecBlobOid and validates task, attempt, generation, owner and acknowledgment. LedgerStore.readHistoricalTaskSpec (2091–2125) verifies historical membership at the task's spec path before loading exact blob. Do not expose arbitrary object lookup or synthesize cursor tokens as a client contract. Historical read still materializes full body internally; reducing explicit spec read IO is not this slice.
