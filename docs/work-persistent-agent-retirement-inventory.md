## 2. External/API, browser, Manager and terminal compatibility

- **MCP / SignalR:** `Server/McpTools.fs:1695-1719` exports `AgentInbox` (self-read may activate), `ObserveAgent` (read-only) and `RegisterAgent`; `:1740-1759` exposes per-Agent instruction edits; `:1798-1815` exposes alerts and notifications. `Client/Modules/OrchestrationApi.fs:2377-2383,2510-2513,2582-2594` dispatches the old inbox/registration/execution transitions. `Client/SignalR/Client.fs:1065-1101,1120-1135` cross-checks acting Agent labels and calls `activateReadyOnActivity`. - **Instruction delivery:** `Client/Modules/AgentInstructions.fs:499-553` resolves project/workspace `AGENTS.md` independently, but the first explicit hierarchy page optionally joins ledger role plus individual instructions through `RoleInstructions.tryResolveAt` keyed by `command.AgentId`. `Server/McpTools.fs:2373-2375` exposes `GetAgentInstructions`. - **Transport identity:** `Server/McpTools.fs:177-233` extracts `agentId`/`fromAgentId` as transport metadata and `:847-853` validates it. This is not the requested credential admission/bootstrap without an Agent ID. Worker 10 owns reservation credential auth; the audit does **not** implement or assume it.
- **Browser:** `Client/Modules/BrowserBridge.fs:391,431-457,829` has `requireAgentCreated` checks on old tab/agent flows. A new Work launch must bind one original `launchId`/credential to the real provider execution and preserve unknown-send handling, without manufacturing a persistent `ReviewAgent` to pass browser checks.
- **Manager & scheduler:** `Client/Modules/BrowserSchedules.fs:42,123,145-149,533-683,726-727` stores `IdleAgentId` and contains `AfterAgentIdle` Manager scheduling/rearm logic. - **TUI:** `ConsoleTui.fs:1494-1543,2101-2117` provides an opt-in Work page **explicitly read-only**, with snapshot adapter injection and claim/Scheduler disabled. Agent page remains separately present. Work-only live binding, filtered views, pending/unknown launches, blocked dependencies and STOP/continuation state still need reviewed implementation.

## 4. Demonstrable blockers (all NO-GO for live cutover)

1. **Legacy writer fence absent:** Active `RegisterAgent`, `AssignTask`, `BeginAttempt`, `ResumeAgent`, reviewer/notification/alert/challenge writers and Manager scheduling still have Agent dependency. No authenticated, participant-wide old-writer/Manager exclusion and in-flight reconciliation receipt exists (`WorkQueueCanonicalMigrationPrepare.fs:281-288`; `docs/Wq10CanonicalMigrationPrepareBoundary.md:56-84`).
2. **Original provenance + composition writer not joined:** `WorkQueueCanonicalCasBinder.publishFreshPractical` loses pinned role and task source-lineage fields; the original WQ02 writer enforces absent role, while the graph writer commits independently. New graph acceptance/revocation cannot atomically fence a WQ02 Available or Claimed stage. `docs/WorkCompositionQueuePositiveCasNoGo.md:7-27` supplies exact code/test trace: negative two-clone safety diagnostic, **zero positive same-transaction acceptance**. Dependency: Worker 12 positive writer and Worker 4 composition authority.
3. **Work execution tools fail closed:** `WorkQueueToolFacade.fs:63-75,248-276` rejects all three live transitions even with a valid operator actor, with no Agent fallback. WQ04 role selection, WQ07 token and WQ03 launch/session/terminal source effects must be checked against original project CAS; `docs/work-replacement-vertical-slice.md:53-64` records NO-GO.
4. **Epoch write/recovery contract absent:** `WorkQueueCanonicalMigrationPrepare.inspect:290-372` is an offline **assessment**, not a writer; it always appends missing old-writer fence, original journal/high-water, role/index conversion, account Preparing CAS, project Prepared CAS, partial-cross-ledger receipt recovery, and authenticated offline review (`:281-288`); `CanonicalPrepared=false`. Dependency: Worker 8 WQ10. Reversible preparation must not be confused with activation.
5. **Registration/STOP mismatch:** Existing MCP/SignalR routes bind input `agentId`; current proposed Work spec still registers UUID on first connect and addresses STOP to it. Need a reviewed initial credential/launch-based protocol and delivery/fence semantics, with no prerequisite legacy `agents/*.json`. Dependency: Worker 10; no credential implementation claimed here.
6. **Work presentation and scheduling are inert:** Work TUI intentionally read-only, Worker 1 Work-first UI dependency; `WorkQueueSchedulerHostLoop.fs:35-49` defaults off, BrowserSchedules Manager loop remains separate. A fresh server with empty data cannot become an independent authority; verified client/account/project Git heads, installed launch/reconcile adapters and fail-closed unknown handling must be proved.
