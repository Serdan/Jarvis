# Client-owned Work Scheduler host loop (default off)

The non-agent Scheduler host seam is in \`Client/Modules/WorkQueueSchedulerHostLoop.fs\`. It consumes only client-owned event hints, fresh **verified Git account/project heads**, and an injected \`WorkQueueReactiveWake.Coordinator.Wake\` callback. It does **not** start from \`Client/Program.fs\`, issue original IDs, reserve account capacity, perform browser/model dispatch, use server telemetry as authority, or alter legacy Agent/Manager/BrowserSchedules scheduling.

## Opt-in and manual rehearsal

Construct \`Host(ports)\` for the safe default: \`Start()\` returns false, \`Notify\` rejects signals and \`RunOnce\` does no Git I/O. For hermetic tests or an explicitly approved future client feature, construct \`Host(ports, enabled = true, fullRescanInterval = TimeSpan.FromMinutes 2.0)\`. Call \`RunOnce [ WorkWakeTrigger.ManualReconcile ]\` to get one synchronous, deterministic rehearsal without any background tasks. Only call \`Start()\` after the operator separately authorizes continuous client scheduling: it creates one worker and one periodic rescan loop, and always queues a startup full rescan. Call and await \`StopAsync()\` for graceful shutdown; \`Dispose()\` also initiates stop and joins except when invoked reentrantly from the host's own callback (which would deadlock), where cancellation exits after callback return.

The injected \`ReadVerifiedHeads\` port must freshly fetch and verify the account and project Git heads against their approved bindings. Missing/invalid evidence fails closed before the \`Wake\` callback. The \`WorkQueueReactiveWake.Coordinator\` independently rereads and rechecks both heads before admission; the host preflight alone is **not** a claim or dispatch authorization. Plug in only a planner that returns immutable, previously recorded original operations and an executor that uses the actual WQ02/WQ07/WQ03 canonical CAS/journal semantics. All host-local pending signals and latest outcomes are disposable hints, never recovery or duplicate-claim evidence.

Supported signals are Work creation/transition, hard-dependency commit, accepted review, integration, capacity release, and manual rescan. Signals coalesce into a bounded in-memory set, with at most one pending pulse; a startup scan and an independent periodic full rescan recover lost hints across client restart. One step calls the coordinator **once**; bounded Git-head retries are managed by \`Coordinator\`. Uncertain outcomes, unavailable heads/account authority, rejected originals and exceptions surface as \`SchedulerHostOutcome.NeedsAttention\` or the contained \`WorkWakeResult\`, with repair guidance; do not silently create a replacement launch/original.

## Remaining production wiring (not authorized here)

No live Work change subscription or capacity/review/integration event bus, UI activation setting, approved project/account binding selection, durable-original planner registration, real browser executor, or production client shutdown registration is provided by this task. Production integration must wire those explicit client-side ports and obtain operator authorization for any real Work claims or browser/model effects. Multi-client safety is enforced by *canonical CAS and original browser journal*, **not** by this local pulse/timer. Never infer inactivity from missing server SQLite \`attributed_agent_activity\`. Do not enable the legacy BrowserSchedules path as a substitute.
