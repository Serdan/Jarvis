# F2 — Typed environment-name list is lossy at client boundary (P2, correctness/validation)

**Frozen source:** `ce1bd9fd7ee60663a300f2405896b84e65ec0d00`.

**Evidence and concrete negative.** `Server/McpTools.fs:1159-1168` accepts any list of strings up to 128 entries and 128 characters per entry. A request `{"settingName":"allowed-environment-variables","operation":"set","value":["SAFE_A;SAFE_B"],"expectedRevision":"<current-hash>","deviceId":"<selected-id>"}` parses successfully as a **one-element typed list**, although `SAFE_A;SAFE_B` is not a valid environment-variable name. `Client/SignalR/Client.fs:548-549` uses `String.concat "," names`; the existing and W24-shared `ClientConfig.updateKey` at `Client/Modules/ClientConfig.fs:325-327` (W24 source `55fdbcb93681abaa07d94cc62da2d2fef6ce59b3`; baseline analogous) splits on **both commas and semicolons** before validating. Thus the invalid one-element list is reinterpreted as `["SAFE_A";"SAFE_B"]`. When those two names are already allowed, the W24 remote expansion check (`:375-383`) permits this apparently unchanged request instead of returning a malformed-list error. Likewise `["A,B"]` is split into two names. This is source-proven list identity loss; no live-client execution was made.

**Impact.** The typed API does not preserve the JSON array element boundary, can accept invalid names, and may report success for a different logical value. It violates the original requirement to reject malformed values before mutation. This finding **does not claim** that remote allowlist expansion is demonstrably possible: the separate W24 remote trust/allowlist guard still needs its independent tests and final integration.

**Minimal bounded remedy.** Validate each typed name against exactly the config's variable-name grammar **before flattening** (no delimiters, empty names or invalid characters), preferably pass an actual typed list to the shared service rather than CSV; preserve exact order/meaning or document canonicalization explicitly. Add negative tests for `["SAFE_A;SAFE_B"]`, `["SAFE_A,SAFE_B"]`, empties and duplicates, and a disposable pre-existing two-name allowlist demonstrating that malformed input cannot be acknowledged as a successful update. Keep local-only confirmation, CAS and W24 custody intact.
