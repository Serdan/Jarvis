Lead-authored next-response alerts and cooperative stop instructions

Goal: Jarvis Lead needs a practical way to interrupt or redirect an agent already working, without terminating its process or waiting for it to inspect its inbox. The agent is cooperative: a clear instruction in its next Jarvis tool response is sufficient. The existing 25/30-minute Working-turn warnings already use this delivery channel. Unify the two mechanisms rather than introducing another communication transport.

Observable behavior

  • Provide a small Jarvis tool for Lead/operator to queue a free-form alert for an exact (project, target agent) pair. A routine direction and a clear STOP message are both ordinary alert text, not new task-state transitions. Example: STOP — Jarvis Lead: Do not start new work. Preserve/commit safe changes, yield to Ready, and end this turn.
  • On the target agent's next ordinary Jarvis tool response, include any pending alert prominently in the same instructions/guidance mechanism that already appends soft- and hard-duration warnings. Preserve the original tool result/error and any existing instruction material. The message should appear without requiring agent_inbox, explicit notification polling, or a new ChatGPT turn.
  • Keep the alert associated with the correct project/agent, available across connected clients and ordinary restarts until delivered or explicitly cleared; do not rely solely on a per-client process cache. A simple bounded one-shot queue or most-recent alert is sufficient. Do not require the target to send an acknowledgement or prove obedience. Define concise best-effort semantics for failure/uncertain response delivery without adding a distributed exactly-once protocol.
  • Keep duration guidance (25-minute soft stop, 30-minute hard stop, existing session warning semantics) unchanged in effect, delivered through the same response instruction aggregation. If both duration and custom messages are present, show both in sensible order; do not let a routine note conceal an urgent STOP.
  • Target the calling agent identity already present on Jarvis tools. Examine job polling and asynchronous/errored responses: a target's next tool response should carry alerts even when it is get_job_result or a failed operation, without erroneously recording job polling as fresh Working activity, starting an assignment, or granting authority based solely on an agent ID label.
  • Lead may inspect or clear an undelivered alert. This is a coordination instruction, not a forced kill, task cancellation, permission revocation, process supervision or task-spec amendment. Agent IDs remain coordination labels; use existing authenticated actor/role context and permissions as appropriate, without new identity infrastructure.

Implementation guidance

Inspect Client/Modules/WorkingTurnGuidance.fs, Client/SignalR/Client.fs (checkWorkingGuidance and toAgentResponse) and the existing typed response Instructions envelope. Prefer minimal reuse of existing persisted notifications/delivery infrastructure if suitable; do not create chat threads, a new queueing platform, kill switches, or bespoke agent manager. Do not conflate custom alert consumption with the currently cached duration guidance. Challenge Lead early only for an actual unresolved requirement, not implementation choices.

Acceptance

  1. Lead queues a stop message; the target makes an otherwise unrelated Jarvis tool call; the resulting response visibly contains the stop instruction, and the agent can voluntarily yield. No inbox read required. Demonstrate a custom non-stop instruction too.
  2. Regression tests cover exact target isolation, multi-device/restart visibility, duration warning coexistence, no alert leakage to other agents, response-error path and job-result polling, delivery/clear semantics and bounded output. Do not degrade normal agent/task activity tracking or implicit activation.
  3. Use .NET 11 Release tests and independent frozen review, then Lead exact-commit integration. Keep this scoped to advisory response injection; do not deploy/restart live client/server or enable unattended Manager heartbeat as an incidental side effect.
