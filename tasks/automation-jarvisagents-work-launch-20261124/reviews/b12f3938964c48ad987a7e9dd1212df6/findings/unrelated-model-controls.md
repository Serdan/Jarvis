# Unrelated visible model controls block a valid launch

At `browser-scripts/chatgpt/launchAgent.js:165`, `picker()` counts every visible `button[aria-label="Select ChatGPT model"]` in the document and returns null unless exactly one exists. Reproduction: render a valid project Work composer and its verified Terra/Medium picker, plus a separate visible model picker belonging to an unrelated surface outside that composer. The global query finds two and `choose()` cannot prove either selection, so the launcher never sends even though the relevant composer remains unambiguous. The added `duplicatePicker` fixture tests only global duplication and labels both controls competing; it does not distinguish an unrelated surface.

The adjudicated correction explicitly requires rejecting genuinely competing relevant controls without rejecting harmless unrelated controls, and binding to the relevant composer where reliable. The document-wide count cannot make that distinction. A composer-scoped association, or other evidence that establishes relevance, with a negative-space test for a visible unrelated picker would address the requirement. This is a source-level constructed scenario; no claim is made that the current live page contains such a second picker.

Separately, the changed Work check at line 524 now treats any visible `data-model-selection-label` anywhere in the document as contradictory on ordinary non-project home, including labels belonging to unrelated UI. This can regress existing valid Work launches under the same condition; scope that check to relevant evidence as well.
