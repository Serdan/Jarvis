# Configuration read failures can disable the fence

Frozen source 18e8707f505338ab28661d36a3094314e4efd153, base 85ec138db0bd61253b6550388f8f9b30a9f4eb6a.

`Client/Modules/ClientConfig.fs`, `capacityFenceModeAt` and `readRaw`: both use `File.Exists` to distinguish absence. .NET `File.Exists` returns false for inaccessible paths and dangling symlinks, not just absent files. If the config containing `capacityFenceEnabled: true` becomes inaccessible because a parent directory loses search permission, or the config is replaced by a dangling symlink, `readRaw` returns empty and `capacityFenceModeAt` returns `Ok Disabled`. The actual BrowserRunInNewTab caller proceeds to browser effects instead of HOLD when configuration is unavailable. The implementation explicitly treats unavailable/invalid configuration as HOLD, and the task requires enabled enforcement before effects. Source-derived reproduction: arrange either condition, then invoke `capacityFenceModeAt` or the actual caller and observe Disabled/send. Existing tests cover malformed readable content but not inaccessible or dangling paths. Candidate remedy: distinguish confirmed absence from access errors and invalid filesystem entries without relying on File.Exists swallowing errors; add disposable path and caller negative tests.
