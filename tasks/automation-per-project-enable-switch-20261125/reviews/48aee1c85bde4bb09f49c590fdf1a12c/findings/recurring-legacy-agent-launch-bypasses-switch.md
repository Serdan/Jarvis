# P1 — Recurring legacy agent launcher bypasses project Automation

Frozen SHA `6305ce4e89cd0daba6d639432f9bbdd8a3f8c12c`; original spec v2 requires gating actual background agent automation before selection and new sends, preserving unrelated browser schedules and explicit manual actions.

**Reproduction (source-traced, not executed):** configure an enabled `Every` `BrowserScript` occurrence for a bound project with `ScriptPath = browser-scripts/chatgpt/launchAgent.js`, valid prompt arguments without `resumeReady:true`, approved browser window/route and ordinary browser permission, and disabled local capacity fence. Leave that project's policy absent or explicitly OFF. At a due occurrence, `BrowserSchedules.isReadyResume` (lines 51–60) returns false. `Program.fs` 430–433 dispatches it to generic `executeScheduledAction`, which authorizes, reads source, waits for connection, checks only local capacity fence and enters `BrowserBridge.runInNewTab` (172–240, especially 227–234). No project Automation read occurs. This is a supported background agent-launch configuration, not an unrelated browser action: `docs/BrowserBridgeSystem.md` line 405 explicitly describes an hourly orchestrator invoking the launcher via the scheduler. A saved recurring launcher can therefore send a new agent prompt while project Automation is off, with no verified project opt-in. This is a source-level counterexample to the all-active-autonomous-route requirement, not a claim about currently saved production schedules or an observed live send.

The older `AfterAgentIdle` Manager route is *not* a current counterexample: `Program.fs` 589–596 hardcodes an error verifier, and `BrowserSchedules.fs` 822–832 prevents its claim. Do not reactivate it. Arbitrary scripts' semantics cannot be inferred generally; no blanket ban on unrelated schedules is proposed.

Candidate bounded remedy: classify the supported recurring agent-launch route independently of the Ready-resume marker (or explicitly retire/fence that legacy recurring route), resolve the canonical target/binding and gate on verified opt-in before dispatch and at its final send boundary. Preserve explicit manual actions, unrelated scheduled scripts/commands, and original occurrence reconciliation. Add disposable registered-dispatch tests for a legacy recurring launcher absent/off/on, disable before send, and an unrelated schedule still executing with Automation off. If the Operator explicitly intends pre-existing recurring agent-launch schedules to be exempt, that would require a recorded narrowing of the original all-background-automation requirement; do not infer it from the old routing comment.
