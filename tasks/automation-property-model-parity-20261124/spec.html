[P1][Automation] Maintain property-model parity across current implementation and composed release

Operator requires property testing to keep up with implementation, not remain a one-time historical exercise. Lead coordinates a recurring development/review obligation and a bounded independent audit of the current Automation frontier. Reuse existing Health coupled recovery/CAS, Challenge transition/index/receipt and Scheduler account CAS/planner/project-effect/host-loop suites; do not build a parallel model framework. Identify exact current accepted and pending source, test model provenance, gaps and owner leases.

Required work

  • For every semantic change, update affected generators, independent reference model and invariants in the same implementation change or explicitly coordinated dependent test change before acceptance of the composed release. Review must check actual model parity, not simply test counts. Nonsemantic edits may record why no model change is needed.
  • Prioritize current Scheduler existing-client-auth simplification, original-bound verified-no-send/reconciliation, reservation occupancy and quotas, roster change, reviewer claim/CAS, provider effect and session outcome, unknown/no-replay and host-loop wake/stop. Exercise meaningful concurrent interleavings and fresh/stale lineage against actual production entry points.
  • Challenges: retain transition/reverse-index/state-machine properties, known subset plus unknown completeness across mixed versions and composition, fresh committed wake exactly once; cover pending and terminal receipt sequences. Health: retain coupled authenticated activity admission and recovery CAS, stale/duplicate/concurrent activity, restart and requalification; ensure optional telemetry pressure never substitutes for liveness evidence.
  • Prefer small independently specified state models, reachable valid generators plus deliberate invalid transitions, reproducible seeds/shrunk traces, coverage of meaningful state/transition classes and negative controls that demonstrate a real fault fails. Do not mirror implementation or weaken existing assertions to make changed code pass. Keep generated cases deterministic/bounded for normal development; add focused real integration tests where a property harness cannot establish semantics.
  • Audit existing tests against actual current source and test targets; distinguish historical evidence from fresh runs. Report missing coverage concretely, assign nonoverlapping corrections to feature owners or dedicated test workers, and ensure accepted exact composition runs the affected property suites. No unnecessary repeated full suite or new release bureaucracy.

Lead should incorporate this into current and future implementation/review assignments, not defer all testing until end of milestone. Coordinate source leases; source/test work only, no deployment or production effects.
