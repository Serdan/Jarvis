# Blocking: late launch can bypass the replacement fence with an ordinary inbox call

Reviewed source `c36c1c58aeed92b2ea1485e8882d9cc15d75c611`. Original pinned specification `6fc4178e74a12f54954f05c6675932bf68968942`, five-minute check-in section: recognize or fence a late check-in so it cannot take authority from a replacement; replacement must not duplicate live execution.

**Evidence:** `Server/McpTools.fs` AgentInbox exposes `launchId` as optional/default empty. `Client/SignalR/Client.fs:1589–1606` invokes `recordCheckin` exclusively for AgentInbox with nonblank LaunchId; all other commands pass `Ok scope`. Lines 1624–1641 record ordinary activity, activate, then execute the command. In `activateReadyOnActivity` lines 407–425 the launch gate is also restricted to nonblank inbox identity; lines 463–482 use legacy `activateReadyAgent` for the None case. The launch identity is merely appended to a model prompt (`Client/Modules/ScheduledReadyResume.fs:946–952`), not bound to an execution/session. Existing clients can omit this optional field; a late model may also omit it or continue with another tool call after rejection. Neither condition is a proof of the original execution having ended.

**Reproduction (source-derived, not run):** A Ready worker receives scheduled launch A, no attributed activity occurs through deadline, authoritative evidence permits replacement B on the same Ready episode. A late A calls ordinary `agent_inbox(projectName,agentId)` without the optional launch ID while B has not yet activated. The ordinary activation path accepts the still-Ready assignment under a fresh random operation ID, rather than checking A's terminal resolution or B's ownership. If B is already Working, A can still access ordinary agent-scoped commands under the same actor label. The explicit late-ID unit test (`tests/ScheduledReadyResume20261125/Tests.fs:120–126,173–178`) only calls `recordCheckin` with A's ID and does not exercise the actual command boundary with missing identity. This violates the late-execution safety obligation independently of the quality of the no-check-in CAS.

**Impact:** Two inference sessions for the same assignment can act under identical agent authority, or a late launch can activate first and deny the intended replacement. Prompt steering is not an authority fence.

**Candidate remedy (adjudicate scope independently):** bind execution identity at the command boundary for scheduled executions (including subsequent calls), or conservatively refuse automatic replacement when the transport cannot distinguish late sessions and provide explicit safe operator recovery. Preserve a deliberate manual activation path that cannot silently let an old scheduled execution use replacement authority. Add end-to-end command-path regression for missing ID, late A after B is authorized, late A after B activates, and ordinary manual dispatch. A model-supplied first-call ID alone is insufficient to fence later commands.
