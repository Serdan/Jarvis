Finding A — taskless Reviewer launch never starts execution

The original Reviewer launch only reads reviewer_inbox, claims a frozen review and acts after claim. AgentInbox does not activate an unassigned NeedsWork reviewer; ClaimReview changes only the review record. An unassigned reviewer therefore remains NeedsWork/Stopped after claiming. A subsequent planner tick can reserve another session for the same claimed review.

Required correction: wire the taskless lifecycle into the actual Reviewer launch path. The launched Reviewer must call its own agent_inbox first to obtain its exact current agent version, then call start_taskless_work as itself before reviewing/claiming work. Manager must never impersonate the Reviewer. A pending/uncertain start must count as in-flight demand and must not generate a second reservation while the first launch/start is unresolved. Reconcile start outcomes by original identity/receipt rather than blindly retrying.

Finding B — taskless Reviewer cannot resume a claimed review after yielding

YieldTasklessWork parks an unassigned Working agent. The planner currently excludes Parked from reviewable states, so an outstanding runnable claimed review is never resumed. Simply treating every Parked reviewer as eligible would override intentional Operator parking.

Required correction: add a durable distinction between a taskless session parked by its normal yield and an intentional Operator park (or an equivalent explicit, versioned disposition). The planner may resume the exact runnable claimed review only when the Parked state is attributable to scheduler/taskless yield and no explicit Operator park/STOP fence exists. After a taskless review completes with no outstanding claim, the reviewer may be reused for unclaimed demand only if it has not been intentionally parked. Preserve existing manual park semantics.
