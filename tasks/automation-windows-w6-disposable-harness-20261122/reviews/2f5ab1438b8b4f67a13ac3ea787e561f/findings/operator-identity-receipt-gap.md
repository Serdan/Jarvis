# P1 — Caller-supplied identity and approval cannot prove a separate disposable OS identity

**Frozen source:** `775e85dc5d70dc17a8fc1c65d7cf3baa84a53b8b` (base `dcac884fc061869572b12a03befc12f11c009f2f`). **Original requirement:** task spec `cbe043e306d0958473174244ab0bd5205814b473` requires a genuinely separate disposable non-admin Windows token/SID or VM, independently attested access denial to the *real* operator profile, and fail-closed gating before source staging/scratch creation.

**Evidence:** In `native-preflight.fsx`, `--dedicated-sid` and `--operator-sid` are both caller arguments. The only distinction check is current token SID == supplied dedicated SID and != supplied operator SID; nothing binds supplied operator SID to the actual operator account. `compose.mjs` likewise accepts a local JSON `--operator-denial-receipt` with self-asserted `operatorProfileDeniedByOs:true` and `approvedByLead:true`; it authenticates neither the author nor an independent Lead/OS attestation. `W6NativeChildGuard.fs` repeats this comparison using caller-controlled environment strings. Native identity, known folders, path and protected ACL checks are real, but they only bind a scratch parent to the *current* token, not to a genuinely distinct token from the real operator.

**Counterexample (source reasoning; deliberately NOT executed on Windows):** A non-admin operator launches `--stage` under her own Windows token, passes her real current SID as `--dedicated-sid`, any other valid SID as `--operator-sid`, uses an operator-owned outside-profile directory with protected owner-only DACL, and writes receipt JSON with the expected booleans. The checks as written can pass despite no distinct OS identity and no verified operator-profile ACL denial. An independent reviewer cannot interpret a caller-authored receipt as an attested privilege boundary.

**Impact:** Violates the original Windows safety precondition. The apparently guarded source-only staging action can allocate under an unverified operator context, even while native test execution is held. Linux 7/7 and Linux negative FSI do not cover this Windows spoof.

**Bounded corrective direction (not a scope expansion):** Bind actual operator identity and operator-profile denial to a separately authenticated, Lead-verified account/VM preflight record or OS-backed proof that the staging process cannot self-assert. Require that proof before `--stage` creates scratch. Keep tests and all probes away from the live operator profile. Add a static/guarded negative case demonstrating rejection of forged operator SID/approval JSON. The exact authentication mechanism is for independent adjudication; do not infer acceptance from a filename or boolean.
