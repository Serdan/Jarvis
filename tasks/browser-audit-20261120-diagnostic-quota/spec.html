[P2][Browser audit] Make optional diagnostic retention recover from disk quota saturation

Finding

Jarvis get_connection_diagnostics returns TelemetryQuotaExceeded: diagnostic disk budget reached. OptionalFeedbackStore applies combined DB/WAL/SHM size limits and rejects operations once at cap, including housekeeping using the same guarded write path.

Required work

Trace optional-feedback storage cap enforcement, WAL growth/checkpointing, retention policy and pruning scheduling. Make quota handling bounded and recoverable: low-priority writes may be dropped but pruning/checkpointing and minimum critical diagnostics must remain operable. Do not silently delete unrelated authoritative ledger, required audit or security evidence. Ensure storage pressure in optional feedback never interrupts core browser bridge or agent execution.

Acceptance criteria

  • Deterministic test fills optional diagnostic store to/above cap and proves bounded prune/checkpoint can recover normal operation.
  • get_connection_diagnostics returns bounded useful data or an explicit degraded result instead of being permanently unusable.
  • Combined DB/WAL/SHM footprint stays within a configured budget after maintenance or reports a clear unfixable fault.
  • Tests verify failure containment: optional telemetry saturation cannot cause main execution/transport failures.
  • Document retention limits and recovery procedure, including tests of crash/restart after quota reached.

Evidence and starting points

Server/Services/OptionalFeedbackStore.fs; get_connection_diagnostics returns TelemetryQuotaExceeded; observed combined ~32 MiB / base ~16 MiB budget.

Boundaries

Writing this task does not authorize deployment, changes to live schedules, live prompt sends, or agent launch. Coordinate with existing work and use actual test and runtime evidence before completion.
