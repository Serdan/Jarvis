# P1 — Final fresh-home tab query invalidates the pre-injection revocation fence

**Frozen source:** `b7033b4b7bcdee0936cf7239a625a4ecaccf3257`, parent `a9e758fa1274b6e036708beb6da055721644fdab`; `browser-extension/background.js` lines 493–511 (especially new await at 501). **Review:** `15cc33b08f8b4f3890403e963b7c7802`.

**Existing security obligation:** explicit operator opt-out / registered-window revocation must prevent any new project script or Send from executing before the irreversible injection boundary. The existing `authorizePageExecution` comment at lines 229–230 explicitly requires permission query to be the last awaited preflight, followed by synchronous revocation checks and immediate injection. This corrective source breaks that ordering for `strictFreshHome`.

**Root cause:** after `await authorizePageExecution(pagePin)` returns null and checks revocation (493–494), the new exact-home block awaits `chrome.tabs.get(registration.tabId)` (501) and checks only URL/pending/status/discarded/frozen. It does not recheck `pageExecutionRevocation(pagePin)` or host permission after the awaited operation. An opt-out during this await changes `allowAgentCreatedTabs` and the authorization epoch, but the code proceeds into `api.execute({js:[{code:wrapper}]})` (507), so side effects can occur after authority was revoked.

**Independent deterministic reproduction (no file mutation, no live prompts):** use the frozen `bridge.test.cjs` harness via in-memory `Module._compile(existingSource + testCase)`. Create a registered `https://chatgpt.com/` agent-created tab. After the first read-only focus `userScripts.execute` resolves, install a `beforeNextTabQuery` hook; let the first post-probe query (inside `authorizePageExecution`) pass, then at the second query (new exact-home inspection) call and confirm `h.message("setAgentCreatedTabs", {allowed:false})`. Continue the composite `executeJs` request with harmless source `document.title`. **Observed:** `queriesAfterProbe=2`, `h.calls.length=2` (focus probe plus prohibited project script), `response.kind=error`, `response.error=OutcomeUnknown:RegistrationChangedDuringExecution`, debugger attach/enable/disable/detach all occurred. The added assertion requiring only one read-only probe failed; process exit 1. That failure is the reproduced security defect, not a baseline test-suite failure.

**Impact:** an operator who revokes agent-created tab authorization during the new asynchronous URL preflight can have a previously requested project script run after revocation, including a possible Send. Post-execution `OutcomeUnknown` cannot undo external effects. This is a source-bound race reproduction; it is not evidence of an actual live prompt send or data leak.

**Bounded remedy:** perform exact-home Chrome tab inspection **before** the final `authorizePageExecution(pagePin)`, so the final permission await plus synchronous pin/epoch/registration checks occur immediately before `api.execute`. Retain the existing exact-`location.href` guard inside the frame wrapper for navigation between the final Chrome check and the renderer. Add a deterministic opt-out (and, if feasible, host-permission/window-revocation) hook at the late tab lookup. No live prompts, deployment, debugger permissions change, or new feature required.

**Review classification:** P1, ChangesRequested on the frozen source because the patch regresses an existing authorization boundary. The preceding Reviewer3 P1 active→background and P2 same-origin navigation defects appear otherwise corrected by the new focus and exact-home checks.
