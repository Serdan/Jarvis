# P2 — Fresh-home debugger precondition is not a time-of-use boundary

**Frozen source:** 64d94fc8115245b1b522c464858c2ee3d9c44b1b; `browser-extension/background.js` lines 361–385, 468–489, plus wrapper at 441–452. The security claim is that privileged DevTools focus emulation is confined to a fresh ChatGPT home renderer.

**Reproduction (offline fixture):** start with a registered background `https://chatgpt.com/` tab. While the DevTools focus command has completed but before the first `userScripts.execute` focus probe, change its `tab.url` to `https://chatgpt.com/c/preexisting-chat`, modeling an asynchronous same-origin SPA navigation. The probe sees visible/focused; the later `authorizePageExecution(pagePin)` only validates origin, not fresh-home pathname; the injected wrapper for an agent-created tab also checks origin only. A generic project `executeJs` expression executes and returns `result` on the existing-chat route. The author-provided navigation test covers a route changed **before** `acquireBackgroundFocus`, not this post-attachment race.

**Impact/scope:** the extension-level privileged fresh-home execution boundary can drift during awaited debugger and userScripts operations. This does **not** by itself prove a launcher prompt was sent into an existing conversation: `browser-scripts/chatgpt/launchAgent.js` lines 5 and 37–44 explicitly reject non-home start URLs. However, the browser bridge accepts other authorized project scripts, and the stated privileged attachment/execution restriction to a fresh home is not enforced at use time. Same-origin race tests are warranted.

**Bounded candidate correction:** once selecting the special background-focus path, bind the exact `https://chatgpt.com/` URL into the frame-side wrapper precondition (not merely origin) and abort before script execution on route drift. Revalidate immediately after debugger attachment; assess whether unavoidable navigation during attach requires an on-navigation detach/fail-closed fence. Add deterministic route drift at focus probe and between probe and user-code execution fixtures. No unsupported assertion of leaked data or live prompt duplication.
