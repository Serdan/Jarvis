# F01 — P1: A new user turn or conversation route is classified as safe-to-close, so cleanup can discard an active conversation

**Frozen source:** `406568403971356a62dcedd3090ba31883c939aa` (base `90ed868d04524d0483ccd979cffb5029d8cf7027`).

**Evidence:** `browser-scripts/chatgpt/launchAgent.js:116-120,150-154` returns `{status:"notSubmitted",reason:"ExistingConversation"}` if a user-turn marker appears during stabilization or just before Send; lines 9-10 and 116 return `notSubmitted/UnexpectedStartUrl` if navigation changes. Those results mean only that *this script* did not click Send. They do **not** prove that the tab has no now-active conversation. At `Client/Modules/BrowserBridge.fs:882-892`, every `notSubmitted` result unconditionally invokes `closeDefinitive()` without evaluating the reason, conversation route, user-turn state, or a separate safe-to-close proof. `browser-extension/background.js:778-809` checks exact agent-created identity and registration ownership, but deliberately does not distinguish an empty new-chat surface from a newly established conversation before `chrome.tabs.remove`.

**Deterministic counterexample (already established by the frozen tests):** The Node tests `a new user turn during restored-draft stabilization prevents submission` and `a route change during restored-draft stabilization prevents submission` expect `notSubmitted/ExistingConversation` or `notSubmitted/UnexpectedStartUrl` with zero script clicks. The bridge fixture `compositeLaunchKeepsUncertainTabButClosesDefinitiveFailure("notSubmitted",true)` expects a close for every `notSubmitted`, regardless of `reason`. Compose these actual behaviors: a new user turn materializes (or navigation to a conversation occurs) while a restored draft is being cleared; the page script correctly declines its own send, then the bridge removes that now-conversational tab. This violates the task's explicit invariant not to close other conversations and not to discard a possibly in-flight/confirmed send. The identity generation pin does not address this semantic race.

**Required correction:** Separate `didThisScriptAttemptSend` from `safeToDisposeCreatedTab`. For `ExistingConversation`, `UnexpectedStartUrl`, and any incompatibility whose state cannot prove an empty/no-turn home surface, retain the tab and surface registration/diagnostics; only automatically close on explicitly evidenced safe pre-send failures (e.g., old draft remains, still at fresh home URL, zero user turns). Make the status/cleanup contract unambiguous for generic scripts; do not infer close safety merely from `notSubmitted`. Add an end-to-end deterministic bridge/launcher state-transition test that feeds both reasons and proves **no** close frame is emitted while retaining unrelated/confirmed conversations, alongside the existing `UnexpectedSendState` case that **must** close.

**Disposition:** Must fix before integration; the changed cleanup policy creates a real unsafe action on a documented transition.
