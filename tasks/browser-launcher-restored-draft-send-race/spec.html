[P2] Fix browser one-shot launcher restored-draft send-state race

Provenance: Reproduced by Jarvis Lead on 2026-11-15 while attempting to launch Reviewer 1 from the registered ChatGPT browser window; two separate BrowserRunInNewTab calls returned {"status":"notSubmitted","reason":"UnexpectedSendState"}, and canonical reviewer state remained Unclaimed. No ambiguous send occurred. New manually created registered tab showed an older restored Reviewer 2 prompt in [data-composer-input-layout] [contenteditable="true"][role="textbox"] with the Send button enabled.

Root-cause evidence

browser-scripts/chatgpt/launchAgent.js clears a restored draft via ProseMirror selection and document.execCommand("delete"), but immediately returns UnexpectedSendState if the enabled Send selector still exists. After manual draft clearing, the DOM textbox was empty while the button was briefly still enabled; on the next observation it disappeared. This is a UI state-propagation race, not proof the prior draft remains.

Scope

  • Make one-shot launch wait boundedly for editor-empty and Send-inactive state after clearing a restored draft, without clicking Send or blindly retrying an uncertain effect.
  • Verify the editor is actually empty, there are no already submitted user turns or unexpected route changes, and React/ProseMirror form state has settled before inserting a new prompt; fail closed with structural diagnostics if not.
  • Preserve existing Chat mode selection, exact prompt verification, new matching user-bubble evidence, one-click submit and uncertain-result behavior. Never submit the old restored prompt.
  • Add deterministic browser-script tests for delayed Send-button disable, no user turn, restored drafts, true unexpected enabled Send state, and double-submit prevention.
