[P1][Challenges] Safe scheduler requeue authority audit

Objective: produce a source-backed authority and state-transition contract for a non-agent Scheduler to reconcile Challenge waits that become eligible. This is a read-only investigation; no code or ledger state changes.

Current behavior to verify

  • Trace Challenge creation, condition satisfaction, operator response, wakeDependents, the durable wait record, and the existing requeueAttempt operation.
  • Confirm exactly when a wait becomes Eligible and whether any current production component automatically invokes requeue after that transition.
  • Identify the actor checks and audit fields in ChallengeWorkflow. Do not call requeue using the blocked owner's agent ID as the actor; that would misattribute a scheduler action as the owner.

Required deliverable

  • A concise state-transition table from Waiting → Eligible → Requeued/Blocked, including every required condition, exact attempt generation, owner state, source lease and expected version/CAS checks.
  • The smallest safe service-actor/operation contract for a non-agent Scheduler to requeue only eligible Challenge-blocked attempts, with distinct scheduler provenance and no ability to bypass unresolved conditions or source leases.
  • List exact files, methods, tests and audit events required for a later default-off implementation; distinguish code authority from production activation authority.
  • Identify whether existing operator-response and Challenge tests already cover idempotency, stale responses, partial satisfaction, restart and repeated wake delivery.

Boundaries

  • Read-only only: no source edits, task assignment, agent launch, requeue, Challenge creation/reply, live schedule change, deployment or migration.
  • Do not use Telos Work/SQLite as a prerequisite. Prefer existing Jarvis Git-ledger state and Challenge workflow.
  • Do not propose owner impersonation or an unrestricted service identity. Any new Scheduler authority must be narrowly scoped and separately approved by the Operator before live enablement.

Acceptance

Deliver the state-transition/authority contract with exact source references and a minimal test matrix, suitable for the Scheduler planner/runtime follow-up. If the current workflow already provides any automatic requeue behavior, prove it from the production call path rather than inferring it from tests.
