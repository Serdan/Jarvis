Approach

  1. Inventory existing Challenge example tests and project testing packages. Check whether FsCheck (or comparable established F# property-test library) already exists; if not, choose the smallest maintainable runner with deterministic seeds, reproducible replay and failing-trace shrinking. Prefer standard library or one well-supported package to a custom generalized test framework. Document the testing rationale and actual test execution budget.
  2. Define a separate simple reference state machine for Challenges, conditions, actor ownership, access, cancellations, reopening, task-block dependency sets, attempt/agent phases and assignment generations. Generate valid and invalid actions: create, resolve, block-condition, reopen, cancel, block-attempt, requeue, duplicate-op replay, mutated payload reuse, stale versions, unauthorized actor, cross-client interleaving and competing CAS. Check the model against actual workflow results after each step; avoid an oracle copied from production branching.
  3. Properties: Challenge Satisfied iff every required condition is Satisfied; Blocked/Pending/Cancelled do not satisfy; Cancelled terminal; only issuer/authorized condition owner can transition; stale version, changed request hash and foreign actor do not mutate canonical state; exact original UUID/payload returns same immutable receipt; version and audit event history monotonic and concordant; no unintended notifications; a blocked attempt with dependencies may requeue only after every required Challenge is Satisfied, with exactly one generation N to N+1 transition, unchanged task/attempt/owner/pinned spec/source lease, and no orphan wait/reverse index; manual zero-dependency blocks require explicit authorized requeue; CAS competing clients admit at most one winner at one version.
  4. Generate index corruption/adverse states separately with disposable bare-Git fixtures: orphaned by-challenge entry for N and N+1, wrong owner, missing/extra reverse edge, stale challenge ID, stale task/attempt generation, duplicated canonical dependency, canceled challenge, and mismatched identity/ref. The verification/projection must fail closed and cannot invent runnable work. Preserve valid historic index generations and do not overreject legitimate history.
  5. Two tiers: fast in-memory/pure model traces for many seeds/steps, plus a bounded sampled set of genuine two-clone disposable bare-remote Git CAS traces. Include explicit restart/re-fetch/competing-writer schedules and failure reproduction, checking authoritative remote state, immutable receipts and actual event/index paths rather than only inbox presentation. Keep Release test wall time reasonable. If the production architecture precludes pure execution, use a model over reference-state transitions plus bounded real-Git runs without duplicating a whole alternate ledger implementation.
