Support copyable browser sign-in links on WSL

In Client/Modules/OAuth.fs, interactiveLogin starts the loopback listener and invokes the Linux shell browser opener. The authorization URL is currently shown only when Process.Start throws. Some openers exit or fail asynchronously, leaving users waiting with no link. WSL users should be able to sign in using an existing Windows browser without installing a Linux browser or helper.

On WSL, display the complete copyable authorization URL and instructions to open it in the Windows browser while Jarvis waits for the existing loopback callback. Skip automatic browser launch by default on WSL. Keep automatic launch on conventional desktops and make the manual link available even if the opener starts but never opens a browser. Start the listener before presenting the URL. Keep callback loopback-only and preserve existing redirect URI, state, PKCE, timeout, exchange and refresh behavior. Surface the URL to the active user, without adding it to persistent logs or telemetry.

Acceptance: cover WSL with no Linux browser or opener, an opener that starts without displaying a browser, conventional desktop auth, and callback validation. Verify a real Windows browser can complete a WSL sign-in over localhost forwarding when available. If host forwarding is disabled or misconfigured, document the limitation without widening listener exposure. Keep this task separate from the Automation milestone critical path.
