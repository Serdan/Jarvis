# P0 scope boundary — publisher issuer is absent; HOLD is intentionally not authentication

**Frozen source:** `a824df7b9189afb6a04cebfa9734a64071856183`; independent Reviewer 1 review `bb9437a1942f489a928a33a36f892cba`. **Classification:** mandatory limitation and follow-up authority decision; not a discovered regression in the intentionally fail-closed HOLD.

## Independently established trust boundary

The old producer `ReviewWorkflow.completeIntegration` invokes `LedgerStore.publishIntegrationTarget`, observing the advertised remote target, verifying source/review/ref and exact T-first/S-second mechanical merge where appropriate, executing an ordinary non-force push and checking readback. It then records `VerifiedNonForceGitPush/v1`. That is a producer procedure, *not proof* to a separate consumer of who executed it. The original canonical CompleteIntegration operation's actor, exact request, Git trailer and v1 fields can all be generated by an arbitrary authorized `LedgerStore.transact` caller. A force-capable other writer can alter the remote target history before that self-attestation.

The candidate `WorkCompositionAcceptanceAdapter.requireManagedCompletionAt` retains original immutable completion and operation argument binding, matched independent Accepted review, source and integration refs, ancestry/mechanical tree checks, and rejection of fresh blank legacy-shaped completion. For **all** remaining managed modern completions it returns `PublisherProvenanceUnavailable("Managed integration lacks independently authenticated publisher execution proof.")` after those checks. The API maps the typed error. `WorkCompositionQueueTransaction.acceptAndRelease` delegates to `checkAt` before any graph/queue CAS. Thus no caller-supplied v1 fields, copied receipt or fabricated operation can newly authorize a production adapter/queue acceptance, even if source/graph/remote look correct. Genuine reviewed B→S or clean I=(T,S) completion also cannot authorize graph acceptance. Availability is deliberately lost.

No independent, privileged, authenticated publisher issuer was established. `OriginalGitWriterAdmissionJournal.withPublicationClassified` is local, default-off (`publish false` without admission), and `RouteCoverageProven=false`; the server `IOriginalGitPublisherAuthority` is an unregistered interface, and its executor is **fixture-only**. A SHA digest, actor string, local 0600 artifact, v1 metadata, immutable ledger operation or normal push output cannot prove an independent issuer. No authenticated pre-v1 managed rollout anchor or operator waiver exists; managed legacy continues to fail closed. Branch-only legacy is a different path.

## Non-authorized paths and limitations

This gate is **adapter/queue-path safety**, NOT a universal authorization boundary. `LedgerStore.transact` is still a general canonical graph writer; a principal with that underlying power could attempt raw graph mutation independently of `acceptIntegrated`. Do not infer access control over generic writers or production Git host branch protection. Do not promote this review into a proof of host credential isolation or source publication approval. The issuer must be a separate protected authority whose durable receipt binds project, ledger epoch, exact original completion UUID/request, task/submission, immutable review/S, remote/ref, observed T, published I, non-force CAS and readback; the verifier must pin issuer identity beyond the generic mutable ledger surface. This **does not exist yet** in the reviewed source.

**Disposition:** Accepting the HOLD, if tests support it, is security-correct only in that bounded sense. Lead/operator must choose and authorize a real issuer before genuine managed composition acceptance can be reenabled. No deployment/cutover, permission claim, source publication, or unknown-effect retry is authorized.
