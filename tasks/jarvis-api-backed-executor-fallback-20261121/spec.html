[P0] Provider-native Jarvis executor as browser-independent recovery path

Owner: Operator. Date: 2026-11-21. Stage: design and hermetic tests only; no API charges or key handling authorized.

Problem: project throughput depends on consumer ChatGPT UI bootstrap, where browser background scheduling, React hydration, model picker and untrusted synthetic Send can prevent agent start even with a confirmed tool call. All projects can stall on one brittle shared UI transport. Existing browser patch 64d94fc8 and synthetic Edge evidence 598f8c33 mitigate the transport but still require privileged debug permission, security review, login and live acceptance.

Required design

  1. Introduce a provider-neutral worker session transport selected by canonical Jarvis agent/task assignment. Preserve existing agentId/inbox, task/lease/review/integrator authority, no Codex-through-Jarvis, structured checkpoints and yield semantics.
  2. First adapter: OpenAI Responses API with role-focused Jarvis MCP tool catalog; bounded tool-call budget and output tokens; streamed progress/heartbeat; exact idempotency and external effect receipt reconciliation. Compatibility with another provider/local models should be explicit.
  3. Hermetic fake-provider suite: worker session start, tool call roundtrip, long prompt/continuation, retry after transport crash without duplicate effect, lease loss, spending cap, provider backoff and quota exhaustion. No browser, ChatGPT consumer account, API key, external requests or production effect in this stage.
  4. Explicit per-project/agent cost and model choice policy. Separately billed API keys must be stored in an approved secret store, not repo, logs or task ledger. No usage until user approves a spending cap and live cutover.
  5. Browser launcher remains compatibility fallback while native runtime proves production acceptance. Native Health/Challenges/Scheduler and original Git trusted-writer publication gates remain authoritative and independently gated; this task does not bypass them.

Acceptance (design stage): reviewed source and docs; deterministic fake-provider end-to-end tests; model capability/role tool filtering; durable operation receipts; measured memory/latency and exact budget/cancel behavior; Operator review of any future live billing or provider deployment.

Evidence: source-only plan docs/LAUNCHER_UNBLOCK_PLAN_2026-11-21.md and synthetic Edge lab commit 598f8c331 in experiment/launcher-cdp-background-lab-operator-20261121. Official Responses API supports remote MCP; ChatGPT subscription and API billing are separate.
