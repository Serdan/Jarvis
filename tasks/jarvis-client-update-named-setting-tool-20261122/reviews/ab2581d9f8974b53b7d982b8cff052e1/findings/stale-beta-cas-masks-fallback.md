**Frozen SHA:** `da4e54cf0205f67fb4d5a5716b888829f979fc2c`. **Path:** `Client.Tests/NamedSettingTwoNative/TwoNativeNamedSettingTests.fs`, disconnected Beta block following Alpha re-registration (approximately lines 249–271). **Requirement:** original named-setting task: stale/offline selected-device refusal *without fallback mutation*; adjudicated Reviewer5 F1 checkpoint11680 explicitly requires a negative against fallback to a different connected client.

It expects IsError and checks Alpha/Beta bytes and revisions unchanged; Alpha remains connected. This is good evidence that the tested request did not produce a successful wrong-device write.

**False-green counterexample (static reasoning, not an executed mutant):** a misbehaving selected-device router substitutes connected Alpha when selected Beta is offline. It sends Beta's revision to Alpha. Alpha's config is different (machine name and other fields), so Alpha's optimistic CAS rejects. The tool returns IsError; Alpha and Beta bytes and revisions stay unchanged; every asserted condition passes. The test does not count or reject dispatch/connection lookup for Alpha, and never constructs a stale request with Alpha's matching revision. It consequently cannot distinguish correct no-fallback rejection from fallback attempted but masked by CAS.

**Impact:** high-risk acceptance-evidence gap on the exact negative-space property that Reviewer5 and Adjudicator2 required. Not a demonstrated production misrouting bug and not a request to change production semantics.
