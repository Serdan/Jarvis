Remove synchronous Git work from routine MCP responses

Observed problem: On Windows FinanceFlow, GetJobResult command work was 0 ms but MCP commandAndReply reached 15–22 seconds. The response-alert decorator in Client/SignalR/Client.fs checks the canonical Git ledger on eligible replies. Windows measured a single LedgerStore.fetch at 5.2–5.5 s and binding verification at ~5 s. Commit bea5f4086 removed one redundant fetch, but a canonical fetch remains on every eligible reply.

Outcome

Ordinary no-alert MCP replies and job-poll controls must not block on a remote Git operation. Maintain prompt, one-shot STOP/operator response-alert delivery across devices and reconnects, without allowing stale or forged alerts or silently losing pending alerts. The Git-backed ledger and its fencing remain the canonical authority; server caches or hints are not a replacement authority. Integrate with existing SignalR invalidation/response and alert mechanisms rather than invent a parallel subsystem.

Acceptance

  • Measure and compare per-stage command, alert check, Git subprocess, and SignalR reply timing on real Windows and Linux. Show fast-path no-alert GetJobResult no longer depends on remote Git latency; document measured p50/p95 under representative concurrent polls.
  • Queue and clear alerts on one client; verify the correct recipient receives STOP on its next practical tool response on another device, including when the tool fails, a job is pending/completed, and after reconnect. Define and test explicit bounded recovery from lost invalidation or disconnection. Do not reduce safety to best-effort notification without reconciliation.
  • Preserve one-shot, durable, source-authenticated, idempotent consumption; prove no duplicate or lost STOP under CAS races, pending job completion, missed replies, and uncertain remote outcomes.
  • Prevent cross-project/agent leakage and permission bypass. Do not activate legacy writers or stateful Work cutover.
  • Maintain or update Client.Tests/ReviewWorkflowTests.fs response-alert contracts; add targeted timing/fetch-count and cross-device tests. Use .NET 11 Release and native Windows verification before shipping.

Lead owns prioritization and delegation to Worker via Manager; Reviewer and Integrator roles retain their boundaries. Avoid solving this only by moving the same synchronous Git fetch to another hot-path hook.

Lead decision: delivery and invalidation

The existing contract is durable pending queue plus at-most-once best-effort delivery: the canonical CAS consumes before response transmission; a lost response after successful consumption can lose the alert. Do not claim exactly-once or lossless end-to-end delivery or invent an acknowledgement from receipt of an MCP response. Preserve this established boundary for this performance task; the earlier acceptance wording about missed replies means explicitly demonstrate and document this limitation, not require a new acknowledgment protocol. Uncertain consumption must be reconciled by its original operation identity and receipt; never blindly replay or deliver unverified stale content.

Use SignalR invalidation only as a hint to schedule background verified canonical reconciliation scoped by account, project and agent; reconnect/startup and periodic bounded reconciliation must recover lost hints. Choose and document a practical bounded interval and test it deterministically. A hint or cached alert is not authority: before consumption or display verify current canonical queue, clear/version race and source binding with existing fenced CAS. Routine no-alert replies and polling must not wait on Git; verified pending alerts may take the existing canonical CAS path. Define behavior during disconnected/unavailable reconciliation honestly, preserve normal response operation, and test queued/cleared alerts, concurrent consumers, failed tools, job responses, reconnect and lost hints. Avoid claiming guaranteed next-response delivery when a hint is lost or reconciliation has not completed. Keep current source lease and all other acceptance and review gates.
