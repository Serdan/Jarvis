# Source/task matrix traceability is incomplete

Original task §1 requires exact commit SHAs, relevant paths/line ranges, task/attempt IDs, review IDs and integration receipts for material claims. Alignment §9.2 supplies frozen source, review and integration commit IDs, but generally no integration receipt or attempt IDs except the older alignment receipt; §9.3 supplies file links without line ranges. §9.5 gives task IDs and lifecycle labels but no ledger snapshot for the current overlay, no attempt IDs and no frozen source/review ID for the later ChangesRequested Recovery review cited in §§9.2/9.3/9.5. Thus a material status/negative claim cannot be independently traced directly from the document, and evidence of accepted-but-unintegrated versus rejected work is less precise than required. The original §9.10 historical alignment precision is a good example to follow. Representative source claims were independently spot-checked at 142f2bd4b2728ea61e18a9d51f7c663c7951e182: JobManager.fs:39,299-300; WorkQueueGitLedger.fs:19; IHubService.fs:7-12; WorkSqliteAuthority.fs:827. The matrix's overall direction is supported by those checks; this finding is not an assertion that any listed SHA is false.

Candidate remedy: add a compact source/ledger evidence table for material status claims with exact attempt and receipt IDs, current ledger snapshot(s), relevant line ranges and the later rejected Recovery review's exact source/decision, or explicitly mark unavailable evidence. No new source work is requested.
