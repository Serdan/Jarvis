# Original release and cutover requirements incompletely carried into the controlling amendment

Severity: material specification defect; original scope, not a new design requirement.

Frozen source ee09fe64821dacece6c708125f7af0bb54d112be; pinned task spec blob 7ef5eca01eb0001705a045a1274384ee0d7c77e4.

1. Task §3 explicitly requires an immutable tag at the accepted 1.0 cut, a hotfix branch from stable/1.x, focused Release/regression checks and independent review, merge back to stable and immutable release tag as appropriate, then deliberate semantic forward-port to main with validation. Orchestration §16.6 instead says only critical fixes 'independently tested and cherry-picked as needed'; it omits immutable tagging, independent review and deliberate forward-port/validation. Its first bullet also declares main already the 2.0 development line even though task §3 conditions this on the stable cut. Alignment §9.7 step 2 lacks the tag/hotfix procedure too. Reproduction: git grep -n -i -E 'hotfix|forward.port|immutable.*tag' <frozen SHA> -- docs/specs/work-stateful*2026-11-17.md returns no matches. Impact: maintenance fixes can be omitted from main or deployed from untagged/unreviewed boundaries; Automation stabilization could be displaced prematurely.
2. Task §5 requires **separate explicit Operator GO** for cutover, DB activation, deployment and Scheduler enablement. Orchestration §16.7 step 8 has one generic 'Activate 2.0 only after a separate explicit Operator GO'; alignment §9.7 step 9 has one GO before enabling Scheduler after DB initialization. Both disclaim current authorization, but neither explicitly preserves the four distinct future approval gates. Impact: a single GO can be read as covering multiple independent effects, contrary to explicit acceptance. Step 2 also says reconcile or quarantine effects; ensure quarantine is an actual fence on stale executions/source writers rather than a mere status label.

Candidate correction: express the conditional branch transition and immutable tags, focused hotfix review/test and semantic forward-port, and enumerate four separate Operator gates with fencing prerequisites in both specs or an unambiguous cross-reference. No branch creation, deployment, source changes or additional implementation scope is requested. Independent adjudication governs any corrective Work; this is the source review finding.
