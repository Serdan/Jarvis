# P1: A resolved review claim can relaunch a still-running reviewer session

**Frozen commit:** `394f485d39514a44a6231867398d1b833af096d5`  
**Locations:** `scripts/manager-heartbeat.mjs:253-273` (`reviewerSessionEnd`), `:300-335` (`reviewerSessionResumedAfterEnd`), `:384-423` (transition from `observed`), and the positive test `resolved canonical claim at a later verified head frees reviewer for other work`.

**Failure:** A canonical review decision proves that the *claim* resolved, not that the reviewer browser session has ended or cooperatively yielded. The new code treats an H2 head without the claim as `CanonicalReviewClaimResolved` and marks the earlier `observed` browser launch `review-finished`. If the latest sampled attributed activity is no newer than the earlier H1 `PostActivityVerifiedReviewHead` proof, `reviewerSessionResumedAfterEnd` returns false and `decide` can immediately reserve the *same* reviewer against another unclaimed review. No separate session-end evidence is required.

**Deterministic valid interleaving:** (1) Reviewer 1 is actively handling claim A in a ChatGPT tab; an earlier Manager pass observes attributed activity and then verifies H1 still has A, recording the ordered proof. (2) On the next heartbeat Manager completes its activity read while Reviewer 1 is still executing; the last sampled activity remains the H1-proven call. (3) Reviewer 1 invokes `decide_review`, creating H2 where A is no longer Claimed, but has not yet yielded/ended the browser turn. (4) Manager's subsequent verified `task_overview` read sees H2, with another review B unclaimed; the snapshot is complete, fresh, correctly ordered and not contradictory. (5) `reviewerSessionEnd` returns `CanonicalReviewClaimResolved`; the planner emits another `UnclaimedFrozenReview` reservation for Reviewer 1, concurrently with its still-running first browser session. The review-decision tool call is not in the earlier activity sample because the Manager sampled activity *before* H2 existed; no activity transport lag or stale snapshot is necessary.

The current positive test for canonical resolution demonstrates the same unsafe reservation without an explicit reviewer yield, but assumes the session has ended. The H1/H2 barrier only orders **pre-decision activity** against the still-claimed head; it cannot prove **post-decision session quiescence**. This violates the task's no-duplicate-session requirement even though the claim is no longer active.

**Required change:** Distinguish canonical review completion from reviewer-session completion. Keep an observed launch unresolved until a positively attributed explicit session yield/end (or equivalent independently verified session-closure evidence), including across the activity-read/H2-read race. Review resolution may release a claim but must not by itself release the observed browser session. Add a regression that interleaves activity sampling, claim decision, H2 observation, and delayed reviewer yield, requiring suppression until the actual session end. Preserve verified relaunch after yield and the existing capacity/restart/dry-run protections. If a session-end signal does not currently exist for taskless reviewers, surface that dependency to Lead rather than treating claim disappearance as one.
