Independent multi-account server audit

Audit current implementation and pending Automation architecture for multiple independent accounts using one server. No collaboration, project sharing or cross-account access. Read-only audit; do not deploy, migrate or implement fixes. Coordinate parallel independent audit slices where possible.

  • Authentication, OAuth subject/account binding, authorization, session and token lifecycle, all MCP and HTTP endpoints.
  • Device/client registration, routing, reconnects, duplicate IDs, request correlation, browser bridge and execution grants.
  • Account/project/agent identity namespaces, ledger and database keys, caches, singleton services, files, logs, diagnostics, backups and deletion.
  • Scheduler, Health, Challenges, quota and resource fairness, concurrent accounts, recovery, restart, cancellation and failure containment; distinguish live and proposed architecture.
  • Audit existing tests and run safe isolated tests if authorized; use two accounts with colliding local identifiers and adversarial cross-account requests. Never access real other-account data.

Produce durable findings with severity, exact code references, reproduction or evidence, remediation and missing tests. Distinguish confirmed defects from risks and unverified assumptions. Explicitly assess whether shared-server operation is safe today. No fixes or cutover without separate authorization.
