# P1 — Public Task/Review write preflight can fail before the operation is journaled

**Frozen source:** `5a24d3da479a2a934e3898e7add99858e394e565` (base `7b589173135178a634495146675dad5db647e5f8`).

**Relevant acceptance criterion:** Under a sustained transport outage, a YieldAgent or other canonical Task/Review write must leave an unambiguous recoverable operation, with its original UUID and safe next action; it must not regress to the incident's absent pending-journal record.

**Source evidence:** `Client/Modules/OrchestrationApi.fs:2323-2344` resolves `LedgerBindingConfig.loadForContext` or `load` *before* it parses `cmd.OperationId` and before `PendingIntentJournal.executeLedgerWrite`. The Review API has the identical ordering at `:2134-2141`. `LedgerBindingConfig.load` and `loadForContext` call `loadAtRoot` (`:227-248`), which calls `loadAtRootWithSnapshotUsing LedgerStore.fetch` and therefore performs real remote Git I/O. The new 3-attempt/12-second DNS retry (`Client/Modules/LedgerStore.fs:439-473`) runs with no ambient `TransportScope` because only `LedgerStore.transact` establishes one (`:2261`). `LedgerErrors.toEffect` emits `OperationId = None` (`OrchestrationApi.fs:49`).

**Concrete counterexample:** Agent S owns Working task T, generation G, and invokes the public `TaskApi.write` with action `YieldAgent`, original UUID U, summary and next action. All remote fetch attempts made by `LedgerBindingConfig.load` fail DNS. The API exits before calling `PendingIntentJournal.executeLedgerWrite`. No durable record for U exists; the returned transport diagnostic says `operationId=none`, and the mapped effect also has `OperationId=None`. No checkpoint or Ready transition is committed (correctly fail-closed), but the exact request is not durably recoverable from the journal. A replacement session/client lacking the original request cannot reconcile U, which reproduces the central incident failure mode under a sustained outage. Identical exposure exists for `ReviewApi.write`.

**Why existing tests miss this:** `Client.Tests/ReviewWorkflowTests.fs:6338+` constructs an already-validated `LedgerBinding` fixture and calls `PendingIntentJournal.executeLedgerWrite` directly. The YieldAgent test at `:6566` likewise skips `TaskApi.write` and the binding-loading preflight. All seven new tests can pass while the outer path fails.

**Required narrow correction:** Preserve the authenticated locally pinned binding and original caller UUID/command as a crash-durable pending intent **before the first remote Git request** in public Task/Review writes; verify the remote trust anchor before allowing any authoritative mutation. Alternatively, any preflight design must meet the same durable UUID+hash recovery contract, not merely return an unjournaled error. Add public API tests injecting sustained DNS failure at binding resolution, assert the U+hash journal record survives and the diagnostic carries U and a single safe action, then restore remote service and assert one canonical Yield checkpoint/Ready transition and one Review operation, each with original-receipt replay. Include stale generation/changed command negative cases.

**Verdict impact:** **P1 blocker, ChangesRequested**. Core ledger-stage retries are valuable, but do not close the incident's public write path.
