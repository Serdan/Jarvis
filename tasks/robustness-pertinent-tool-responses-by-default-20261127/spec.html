Pertinence by default — core Jarvis design principle

Explicit Operator decision 2026-11-27: tools should return pertinent information by default. Unfiltered state wastes tokens, distracts agents and can exhaust context or transport. This applies to Jarvis 1.0 and future Work/2.0 surfaces, not merely TaskOverview.

Design contract

Return a deterministic, bounded, task-oriented projection at the producing boundary; default scope follows the purpose of the tool, explicit query and caller's relevant assignment/role where appropriate. Include the facts, exact references, state transitions, uncertainty, negative evidence and diagnostics necessary for the next correct action. Avoid unrelated history, repeated immutable instructions, redundant metadata and verbose receipts. Filter before serialization/transport, not in the consuming agent. Historical/verbose detail remains available by deliberate exact lookup, explicit filters or snapshot-consistent paging. Expose scope, totals, omissions and continuation when needed; do not silently truncate, hide necessary evidence, invent completeness, or replace deterministic semantics with LLM relevance ranking. Authorization is independent of relevance. Preserve canonical records and auditability.

Deliverables

Record principle in the canonical repository architecture/development and agent command-surface guidance; reconcile existing docs/decisions rather than proliferating competing standards. Audit registered MCP tools, common response envelope, agent/reviewer inboxes, task/review/work queries, mutations/receipts, job and diagnostic responses. Measure actual default response bytes and representative token burden where practical; classify necessary, optional/retrievable, redundant and safety-critical content. Identify concrete high-value violations with source/route evidence, proposed purpose-specific default projection, explicit expansion, backwards-compatibility/migration and tests. Produce prioritized nonoverlapping implementation tasks for genuine gaps, reusing existing robustness-bounded-task-overview-20261127 and other existing tasks rather than duplicating them. Prioritize broken default routes and high-frequency agent calls. Do not turn audit into a wholesale unrelated refactor or build a generic query language without evidence.

Verification

Define review and regression criteria for new/changed surfaces: bounded default results at realistic scale; completeness within documented scope; deterministic ordering and exact snapshot-bound continuation; explicit full retrieval; no hidden state-changing effects; preservation of authorization, provenance, unknown/blocked states, idempotency and actionable errors. Compare actual registered route outputs, not just DTO tests. Independent review of docs/audit and later implementation separately. Lead coordinates leases and prioritization; no live deployment or production activation.

Operator clarification: deterministic decision-ready derived information

Do not make agents perform routine deterministic calculations or infer policy outcomes from raw fields. Observed ObserveAgent returns lastSeenAtUtc and observedAtUtc; Interpreter repeatedly calculates elapsed time and compares it against the configured Health threshold. Provide age at observation (e.g. lastSeenAgeSeconds), and where supported by authoritative existing policy, typed liveness/recovery eligibility and reason. Keep observed timestamp/source and clock provenance available as needed; distinguish local cache from server-authoritative activity, missing/invalid/future timestamps, nonworking state and configured policy. Never label an agent dead solely from an untrusted local clock, infer recovery permission, or duplicate Health authority. Use the same principle across counts, deadlines, durations, job readiness, review eligibility and other repeated arithmetic/classification: compute once at the authoritative producing boundary; retain raw evidence on demand. Audit actual routes and create narrow nonoverlapping implementation tasks, testing 599/600/601-second boundaries or actual policy equivalent, unknown/future/stale evidence and observation purity. Avoid decorative derived fields that do not support a decision.
