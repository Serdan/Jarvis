## Malformed Unicode path escapes the machine-readable evidence contract

**Original obligation:** Produce bounded machine-readable evidence with explicit verified/unknown/mismatch dimensions; test malformed manifests. README also promises JSON and exit 2 for invalid manifests. This is a defect within the existing scope, not a new threat model.

**Frozen source:** c0e110c11c1fb8615b2ac1868972951952bb25f8, scripts/release-provenance/verify.py lines 42–43 (explicit_path), 77 (lstat), 267–271 (artifact catch), 313–317 (CLI catch). Python json accepts an escaped lone high surrogate; explicit_path only checks length and NUL. The filesystem raises UnicodeEncodeError, which is not an OSError or InvalidEvidence. The same issue exists for receipt reference paths through load_receipt.

**Independent reproduction:** Extract exact verify.py using git show SHA:scripts/release-provenance/verify.py into a temporary directory; serialize a manifest with schema 1, source commit 'a'*40, tree 'b'*40, artifacts [{'id':'client','path':chr(0xd800),'target':{'product':'JarvisClient','rid':'linux-x64','configuration':'Release'}}] using json.dumps. Execute python3 -B verify.py manifest.json. Observed on Python 3.14: exit 1, stdout empty, stderr traceback UnicodeEncodeError at path.lstat. No repository needed. Exit 1 is reserved for mismatch, yet no evidence report exists. This breaks consumers' ability to distinguish invalid input from an actual artifact contradiction. Not a false verified result.

**Candidate remedy (not a prescribed requirement):** reject non-encodable or surrogate-containing manifest artifact and receipt paths during validation, or normalize filesystem encoding failures into the documented invalid/unknown result. Add CLI regression for escaped lone surrogate in both artifact and receipt path. Preserve normal Unicode paths and existing distinction between absent evidence and invalid manifest. Independent adjudication determines proportional correction.
