Unify queued assignment updates

Priority: High. Scope: reissue_assignment, adopt_task_spec and related queued-assignment workflow.

Agents and Leads should express the intention update an unstarted assignment without selecting a tool based on where the new specification originated.

  • Review and consolidate reissue_assignment and adopt_task_spec; handle replacement instructions and adoption of current canonical spec in the same public flow.
  • Let Jarvis manage the issuance generation, receipt invalidation and exact spec OID correctly; reject changes to an already Working agent.
  • Preserve source provenance, immutable issuance history, retries, and strict assignment ownership.

Acceptance: One self-explanatory assignment-update tool; tests for updated instructions, updated canonical spec, retries, stale changes, issued receipts and already-started attempts. Remove old tool exposure only after parity is demonstrated. No deployment without approval.
