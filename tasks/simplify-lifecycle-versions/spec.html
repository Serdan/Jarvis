Reduce version and generation arguments in agent lifecycle tools

Priority: Medium-High. Depends on: simplification of redundant lifecycle and assignment operations.

Current operations demand expectedAttemptVersion, expectedAgentVersion and assignmentGeneration for routine calls, although Jarvis can read these from the canonical ledger.

  • Design a normal public form such as resume_agent(projectName, agentId) that resolves the active assignment and current versions in the same verified ledger transaction.
  • Keep explicit optional expected versions for callers that need optimistic concurrency preconditions.
  • Ensure resolution cannot silently act on a newly reassigned task when caller identity/context is stale; decide which identity and task assertions are necessary.
  • Apply to other routine yield, checkpoint and completion calls where it improves usability, but retain necessary text and evidence inputs.

Acceptance: Simpler default calls; correct atomic concurrency checks; no accidental action on a different assignment; tests across reissue, concurrent clients, idempotent retries and session recovery; protocol/catalog documentation updated. No deployment without approval.
