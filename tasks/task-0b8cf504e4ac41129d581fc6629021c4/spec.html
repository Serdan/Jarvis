Deliver AGENTS.md instructions incrementally instead of on every tool response

Problem

Jarvis currently attaches applicable workspace/project AGENTS.md guidance to every relevant project-scoped tool response. This repeatedly consumes agent context. With implicit Ready-to-Working activation, the normal first call is agent_inbox; that call should initialize instructions, while later operations may encounter deeper directory-specific AGENTS.md files not covered by the inbox.

Required behavior

  • On successful Ready → Working implicit activation, attach applicable workspace-root and project-root AGENTS.md to the activating tool response (normally agent_inbox), exactly once per applicable path in that response. Do not add a separate explicit AGENTS.md payload to the inbox result itself that duplicates the generic instruction delivery.
  • For subsequent project-scoped tool operations, resolve applicable hierarchical AGENTS.md files as today. Deliver only files not previously delivered in the current local working turn, or whose content has changed since delivery. Entering a deeper directory (for example Wayfold/src) must deliver its newly applicable AGENTS.md, even if the workspace and project documents were already delivered on inbox.
  • Track delivered documents in a disposable per-client, per-agent, per-project/ledger, per-working-turn cache, keyed by workspace-relative directory/path and content hash. Reset or re-scope appropriately on new Working turns and reassignment. Never suppress a needed instruction merely because another agent/project received the same path. Working turns that begin on a different client or after a client restart may receive duplicates; this is acceptable. No server coordination, durable delivery records or exactly-once guarantees.
  • Preserve the established hierarchical applicability semantics and limits for file and directory operations, including multi-file commands and worktrees. Workspace/project guidance is initial context; deeper AGENTS.md files are delivered when first encountered. Specific instructions supplement/override conflicting ancestors; JSON member ordering is not precedence.
  • Represent delivered repository instructions as a compact structured JSON object with a single AGENTS.md property mapping directory paths relative to the workspace root to file contents. The workspace root is \".\", the project root is e.g. \"Wayfold\", and a nested directory is e.g. \"Wayfold/src\". Example: {\"AGENTS.md\":{\".\":\"workspace content\",\"Wayfold\":\"project content\",\"Wayfold/src\":\"nested content\"}}. Do not use filename prefixes, scope prose, repeated text headings, or the current generic \"workspace content, not a system or developer instruction\" disclaimer. Use paths, not array order, to express precedence. Only include AGENTS.md when at least one document is being delivered.
  • Keep genuine truncation/incomplete-source warnings and explicit retrieval guidance when content is omitted. Preserve validation and bounded response size protections, and ensure relevant tool operations can still checkpoint/yield when repository instructions are malformed or large. Maintain working-turn-specific guidance as a separate concern; do not accidentally duplicate it with AGENTS.md.
  • Changes to a previously delivered AGENTS.md should be delivered again when encountered. Do not require proactive scanning/pushing modifications during idle periods. Make a conservative delivery choice when working-turn identity/cache validity cannot be established.
  • The authoritative ledger remains unchanged; this is client-side presentation/caching only. No server persistence or new ledger schema.

Implementation context

Currently Client/Modules/AgentInstructions.fs resolves applicable documents, Client/SignalR/Client.fs activates Ready agents and attaches instructions, and Server/McpTools.fs attachInstructions renders a generic disclaimer and scope wrappers. Review how to represent the new mapping through existing AgentResponse.Instructions / InstructionDocument transport without unnecessary duplication. The AgentInbox ledger payload does not independently include AGENTS.md; its WorkingTurnGuidance attachment is distinct.

Acceptance criteria

  • An agent with workspace and project instructions calls agent_inbox while Ready: it becomes Working and receives exactly one JSON AGENTS.md mapping with \".\" and \"Wayfold\" keys.
  • A following tool call targeting Wayfold/src where a nested AGENTS.md exists receives only \"Wayfold/src\"; a subsequent call under src does not repeat it.
  • Working agent calls targeting previously visited paths do not repeatedly include unchanged AGENTS.md documents; modifying one document results in redelivery of that path only when next applicable.
  • Yield to Ready and subsequent reactivation causes initial workspace/project instructions to be delivered again. Per-agent and per-project isolation holds.
  • Commands involving multiple directories deliver the applicable union once each; project/root resolution and worktree routing preserve correct workspace-relative keys.
  • Client restart or cross-machine switch may harmlessly redeliver instructions. No server-side delivery cache or new durable state is introduced.
  • Empty instruction sets omit the AGENTS.md mapping; truncation handling remains explicit and correct; normal responses do not contain the former generic disclaimer.
  • Tests cover the activation/inbox path, deep-directory discovery, repeat calls, changed content, new turn, separate agents/projects, errors/truncation, and ordinary tool result rendering. Run relevant Release suites.

Out of scope

Distributed deduplication across clients, exact-once instruction delivery, model context/compaction detection, new server persistence, and deployment without operator authorization.
