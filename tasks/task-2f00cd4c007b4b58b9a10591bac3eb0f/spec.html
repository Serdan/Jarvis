Register an agent with optional role and task

Purpose: Make the common agent-creation flow a single call while preserving the existing bare register_agent behavior. Today callers must independently register, attach a role with a version check, and assign an Open task with a caller-created attempt UUID.

API and semantics

  • Add optional roleId and taskId arguments to register_agent(projectName, agentId, ...). No breaking changes to existing callers or the independent attach_role/assign_task APIs. A single role is sufficient for initial registration; additional roles can be attached later.
  • Apply registration, optional role attachment and optional task assignment atomically in one canonical Git ledger transaction, not as three independently committed operations. Validate the referenced role exists and that the task is Open, has an intact canonical spec and no owner; if any prerequisite fails, create nothing. Preserve the existing authenticated actor attribution, project binding, role validation, task exclusivity, and operation-ID replay/conflict behavior.
  • When taskId is present, generate a fresh stable attempt ID inside the operation and create the usual queued attempt, issuance/assignment generation, pinned spec, task InProgress update, and agent Ready state using the same invariants as assign_task. Return the new attempt ID and setup result. A task-assigned agent is not automatically Working.
  • Without a task, the newly registered agent remains Stopped/Parked with no assignment; attaching only a role never activates the agent. Without a role, no persistent instruction config need be created. With a role, establish the normal persistent role membership from the outset; no role-derived permissions are granted. If neither option is supplied, behavior is unchanged.
  • Do not launch a browser tab, resume an agent, infer a task from its role, create placeholder tasks, or silently overwrite an existing registered agent. Taskless execution remains a separate concern.

Acceptance

  1. Test all four combinations: bare registration; role only (Parked); task only (Ready and queued attempt); role plus task (both applied exactly once). Confirm ordinary agent_inbox resolves the attached role and pinned task specification.
  2. Missing role, missing/non-Open/owned task, corrupt spec, duplicate agent ID and simultaneous conflicting registrations cause explicit failure with no partial registration, role membership or assignment writes.
  3. Duplicate requests with the same operation ID and arguments return the same registration/attempt receipt; an operation ID reused with changed arguments is rejected. Concurrent task claim/registration races cannot double-assign.
  4. Existing separate register/attach/assign tests still pass; run .NET 11 Release tests and obtain independent frozen review before merge/deploy.
