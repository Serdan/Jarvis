Durable role and agent instructions independent of task assignments

Feedback: f099e39dbf1a472fa2d64f8b9c7b4a44; 8af0b0c68b374f1caafaada9be9aa24b.

Problem

Stable responsibilities are currently embedded in long-lived placeholder tasks, and agents sharing a role cannot reuse one canonical definition. Instructions must outlive an individual task and be recoverable on new sessions without task pseudo-assignments.

Model

  • Define versioned, Git-ledger-backed Role records scoped to project/ledger (ID, human-readable purpose, instruction body); allow multiple agents to reference the same role. Define optional versioned per-agent instruction body/overrides independently of assigned task.
  • Expose explicit creation/update/read/list/attach operations with optimistic concurrency and durable provenance; use typed records and deterministic authorization. Do not treat role membership as permission escalation or activity.
  • Include applicable role and per-agent instruction documents automatically with agent_inbox and get_agent_instructions, separate from the path-keyed AGENTS.md object. Document deterministic precedence across global, workspace, project/directory, role, agent and assignment-specific instructions without allowing subordinate docs to undermine higher-priority restrictions.
  • Preserve actual instructions and semantic history across role edits, assignment changes, project checkout changes and restarts. Prevent arbitrary changes from rewriting pinned task specs or historical attempt evidence. Decide and document whether a role instruction update is picked up at the next turn or next instruction fetch.
  • Coordinate with incremental AGENTS.md delivery (task-0b8cf504e4ac41129d581fc6629021c4) and account-global AGENTS.md proposal; do not conflate instruction delivery caches with canonical instruction authority.

Acceptance

  1. Reviewer 1/2/3 share one Reviewer role; role edits appear at documented boundary, per-agent overrides remain distinct, and none requires an assigned task.
  2. New and resumed sessions retrieve all applicable instructions with unambiguous scope, precedence and hash/version; no duplicate AGENTS.md content.
  3. Unauthorized changes, conflicting version updates, missing/removed roles and concurrent edits are detected with stable error behavior; historical task and checkpoint references remain valid.
  4. Tests cover serialization, authorization, versioning, instruction resolution/caching, multi-agent and multiple projects; Release suites pass.

Out of scope: taskless Working transitions themselves (separate dependent task), automatic agent launch, replacing repository AGENTS.md. Do not deploy without operator approval.
