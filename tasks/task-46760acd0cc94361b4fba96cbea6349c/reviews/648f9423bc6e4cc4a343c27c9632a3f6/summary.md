## Verified implementation strengths

- `ReviewWorkflow` stores durable recipient-owned preferences in `records/notification-preferences/{agentKey}.json` distinct from assignment and existing notices; only actor=recipient can request `SetNotificationSenderBlock`/Mute inside the existing agent-label trust model. Project-qualified sender keys and `MuteAll` allow targeted/general blocks, each optional bounded (<=512 UTF-8 bytes, no controls) direct-tool autoreply. Unblock/unmute reversible; existing pending messages not deleted/implicitly acknowledged. BlockedSender count capped at 32; preference records have versioned CAS.
- `NotifyAgent` performs the decision in the **same** destination-ledger transaction as any inbox write; a blocked message produces a durable non-inbox `records/notification-suppressions/{operationId}.json` receipt with no `notifications/{id}.json`. `notificationDelivery` reports typed `Blocked`+recipient-approved autoreply or `Delivered`+notificationId, preserving original result on operation-id retry even after preference changes. No recursive notification generated by autoreply; explicit sender text not otherwise exposed. The suppression receipt does consume durable ledger storage for every unique blocked operation, but prevents hidden inbox growth and supports deterministic replay.

Core queue/canonical assignment/review lifecycle is unchanged. ## P1 blocking defect — canonical project aliases bypass block

See `findings/p1-source-worktree-alias-bypasses-recipient-block.md`.

`Client.ProjectPaths.ProjectTarget.identity` explicitly resolves `Jarvis::registered-worktree` to the same canonical project `Jarvis`, but `Server/McpTools.fs` cross-project `NotifyAgent` preserves the raw `projectName` as `SourceRef` after routing/verification. `ReviewWorkflow.setNotificationSenderBlock` stores the literal configured project string; `notifyAgent` matches it by raw equality to literal incoming source. Thus a perfectly valid worktree-qualified source selector is not blocked by a recipient's `Jarvis/Owner` rule.

Added one independent negative NUnit test **only to a temporary detached frozen checkout** `/tmp/jarvis-reviewer1-block-alias-49fb`: `ProjectWorktreeSelectorMustNotBypassRecipientSenderBlock`. It verifies canonical project alias equality, sets a block for `Jarvis/Owner`, then sends through the real destination-ledger `notifyAgent` using `Jarvis::review-worktree/Owner`. **Expected `Blocked`, observed `Delivered`**, exit 1, job `afcc58e974554a198f2a0089d39bccb2`. Test models source verification rather than opening a complete Server+SignalR path; the public routing source inspection establishes that registered worktree selectors are forwarded unchanged. This defect enables unwanted durable inbox entries and directly violates the defining P1 requirement.

**Required:** after canonical source verification, normalize source identity independently of checkout alias for both block rule keys and send decisions. Enforce equal canonical source project and sender identity across main+registered-worktree selectors; treat alias of destination itself as local when appropriate. Add production-routing positive/negative tests for same/different projects, canonical aliases, autoreply, replay and zero inbox writes under a block. Keep actual source project provenance and fail closed if unresolved.

## Review-pool instruction scope to verify during correction

The new `AGENTS.md` is in the **Jarvis project repository**, not an account-global or shared reviewer-role instruction. Agents whose task project is Wayfold or Favn will not necessarily receive this exact project-specific prohibition on pinging named reviewers. The shared workspace instruction already discourages routine notifications, but to meet the spec's **all-agent reviewer-pool-only guidance**, the integration/deployment owner should explicitly propagate/attach authoritative policy across affected projects/roles, or implement a canonical role-checked enforcement mechanism (not name-prefix matching). This is a rollout scope concern in addition to the reproducible P1 defect; it is not a claim that other project ledgers were modified.
