Risk

The bounded process executor introduces native Windows Job Object assignment and signaling and macOS setsid/libSystem group-host behavior. Linux tests exercise group cleanup, but Linux cross-compilation does not prove these native lifecycle paths are correct. Do not publish new Windows/macOS client artifacts using this implementation until representative native tests pass.

Validation

  1. On native Windows verify managed dotnet host, framework-dependent apphost, and single-file helper startup; named EventWaitHandle barrier; Job Object assignment before child launch; stdin ClosedInput/InheritInput/TextInput; cleanup after normal exit, deadline expiration, cancellation and parent early exit; retained stdout/stderr descendant handles; no survivors and bounded completion.
  2. On native macOS verify libSystem.B.dylib setsid/kill linkage and helper launch; same group ownership and descendant cleanup scenarios, including early parent exit and both output streams held open.
  3. Record host OS versions, .NET SDK/runtime, exact test commands, outcomes, process-tree evidence and any platform-specific corrections. Add deterministic regression tests where needed, then review and rerun on affected platforms.
  4. Keep ordinary Linux source integration independent from this cross-platform distribution gate; do not claim runtime coverage from static builds.

Acceptance

Reproducible native smoke evidence on both Windows and macOS or an explicit platform-release exclusion. All relevant focused and full Release tests pass on validated platforms. No release/deployment implied by task creation.
