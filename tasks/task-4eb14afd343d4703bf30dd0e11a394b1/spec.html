Guarantee end-to-end deadlines for RunCommand and child processes

Priority: P1. Finding: JRV-2026-11-02. Review: docs/reviews/2026-11-07-deep-review.md (baseline e50c24af).

Problem

Client/Modules/ClientShell.fs:66-137 waits for the immediate process and then blocks unconditionally on stdout/stderr drains. Descendants retaining inherited pipes can keep the command pending forever after their parent exits. Review other direct process launchers for the same class of bug.

Relevant code

Client/Modules/ClientShell.fs; Client/Modules/ProjectPaths.fs:159-210; Client/Modules/JobManager.fs; Client/Modules/LedgerStore.fs; Client/Modules/ProjectCreation.fs; Client.Tests/ClientShellTests.fs

Implementation requirements

  1. Specify a single monotonic end-to-end deadline covering launch, process exit, draining both streams, cancellation, descendant cleanup, and reaping. Ensure that expired commands always return a finite result with typed timeout state and bounded captured output.
  2. Define process-tree ownership correctly across platforms (Unix sessions/process groups; Windows Job Objects). Terminate descendants when timeout occurs even if the immediate parent exited. Do not block on an unbounded WaitForExit, Task.Result, or pipe EOF.
  3. Reuse shared primitives where beneficial; do not hide the timeout by merely increasing server/request timeout. Keep operational distinctions between bounded RunCommand/RunProjectTask and intentionally long-lived StartJob.
  4. Handle errors during startup, stream drainage, cancellation and cleanup; avoid runaway background child processes or leaked file descriptors. Document precise time-limit guarantees and supported platforms.

Acceptance / verification

  • Subprocess fixture exits immediately while a descendant keeps stdout and stderr open; the command returns TimedOut within the configured deadline plus a small bounded cleanup allowance and leaves no controllable surviving child.
  • Normal exit, timeout, failing executable, heavy stdout/stderr, early parent exit, and cancellation tests pass. Exercise Linux and Windows paths where CI permits.
  • Full Client Release suite passes; any shared executor refactor maintains existing command behavior and permission authorization.

Boundaries

No default restriction on permitted executables beyond existing local permission policy.

Review the design and implementation; correct findings and re-review until accepted. Prefer long-term correctness to quick fixes.
