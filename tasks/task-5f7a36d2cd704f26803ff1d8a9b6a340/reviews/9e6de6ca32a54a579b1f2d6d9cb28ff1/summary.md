## Correctness and race behavior

- `Client/Modules/ReviewWorkflow.fs` adds a **read-only canonical** `inspectAutomaticActivation` at one fetched ledger snapshot. It verifies actual current agent, assignment, task lifecycle, task attempt identity/ownership and Queued/Started phase; `Closed` or other terminal task is **ActivationIneligible** and cannot be auto-started merely because retained assignment+Execution=Stopped derives the public agent State=Ready. Invalid phase/ownership is likewise ineligible, not a reason to forge Working.
- `Client/SignalR/Client.fs` only attempts `activateReadyAgent` after that canonical check, rather than trusting a 2-minute in-memory Ready cache as proof of task eligibility. On an ineligible assignment it invalidates local cache and proceeds to the requested self read with no activation or fabricated state-change evidence. If an eligible task changes between snapshot and activation CAS, a StaleEntityVersion triggers a **fresh canonical reinspection**: ineligible (including concurrent task closure or genuine concurrent activation) is safe to read without forcing Working; still eligible surfaces a specific current-task conflict. It does not reset Working clock on a successful concurrent start.
- `CompleteAgentWork` is deliberately exempted from predispatch automatic activation. `ReviewWorkflow.completeAgentWorkWithSession` already accepts a genuine **Started** attempt in either Ready/Stopped or Working state, with task lifecycle `InProgress` or `Closed` and expected agent/attempt generation checks. It atomically records a **Completion** checkpoint, finishes the existing attempt and clears assignment by entering Completed/NeedsWork, **without** reopening the task, fabricating new source/integration evidence or autoactivating Working. A Closed **Queued** attempt cannot be spuriously completed.
- The response preserves explicit `InboxActivation.ActivatedByThisCall=false` for closed self AgentInbox, empty `AgentStateChanges` for read-only observation, and precise changed owner ID after actual completion. Source code changed no authentication, admin workflow or credential handling.
