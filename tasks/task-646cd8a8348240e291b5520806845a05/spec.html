Problem and root boundary

The journal preserves original requests when a write fails or its outcome is uncertain. Current pending_operations and reconcile_pending_operations correctly expose them; acknowledge_pending_operation deliberately retires only a matching Applied receipt. There is no supported safe operator workflow for locally pending operations absent at verified head, especially commands whose original public API was removed (e.g. ResumeAgent). Retrying through a new request can change session-dependent command JSON and trigger 'Pending operation UUID reused with changed input'. Repeated new UUIDs or ad hoc file removal do not solve recovery. A missing receipt is not a definitive failed push.

Required design

  1. Provide a compact, actionable per-project summary of outstanding pending intents by age, action, actor and verified reconciliation disposition. Support targeted inspection of exact persisted command/version, receipt proof, provenance, and affected task/agent without dumping hundreds of full request JSON payloads by default. Retain the current detailed inspection option. Do not expose session tokens unnecessarily in summaries.
  2. Define a typed outcome/disposition model for remote Applied and matching, remote identity mismatch, currently absent / outcome uncertain, binding mismatch, replay rejected as stale, and explicitly superseded/abandoned by an operator. Names are illustrative; do not collapse absence into certainty. Keep reason/provenance and immutable local audit evidence.
  3. Add an explicitly operator-authorized retry saved intent path, where permissible, that replays the exact stored action/fields and original operation UUID through the current typed ledger writer, never fabricates a new session or silently modifies command identity. Validate the active binding identity, authorization, expected state/version, command allowlist and current canonical snapshot. Do not allow retired commands to bypass newer security or lifecycle invariants. The internal dispatcher already retains a compatibility branch for legacy ResumeAgent; inspect whether it can be exposed safely for exact retries without restoring ResumeAgent as a public routine agent tool.
  4. For an intent no longer applicable (e.g. agent already resumed through automatic activation, task/attempt generation changed, equivalent work superseded by another UUID), support explicit supersede/abandon disposition after structured comparison with current canonical entities and any related later operation. Preserve/export a durable local archived record and operator reason; do not mutate the canonical ledger or invent an Applied receipt. No silent deletion, automatic age-based cleanup, auto-replay, or blanket clearing.
  5. Quarantine identity mismatches, invalid binding and malformed journals separately. Never acknowledge or retry a mismatched UUID as if it matched. Require exact verified remote request hash for the existing successful Applied acknowledgment; preserve original behavior. Explain what to do when a previously uncertain push arrives after an operator superseded the intent.
  6. Ensure journal growth remains bounded/operable without losing evidence, including current listAtRoot hard cap of 1000 records. Triage must remain possible before reaching the cap; archive/stale retention policy must not rely on trusting absence as proof. Distinguish journal storage pressure from failed ledger writes.
  7. Keep project/ledger/epoch identity checks, Git CAS and idempotency behavior, no rebase or forced rewrite, and a single authoritative remote ledger. No server database, automatic workflow engine, background retry loop, or new routine ResumeAgent MCP tool.

Acceptance and regression tests

  1. Simulate a push failure before acceptance, a lost response after acceptance, and delayed acceptance. Same-UUID replay/reconciliation returns correct evidence and cannot produce a duplicate mutation. Missing at a snapshot is never represented as proven failure.
  2. Reproduce a protocol-3.57 ResumeAgent entry with saved session context; safely recover or explicitly supersede it without changed-input validation or false current activity. Confirm no public normal resume_agent tool is restored.
  3. Two different requests sharing a UUID remain IdentityMismatch/quarantined. Invalid binding and corruption cannot be bypassed by retry or archive; preserve diagnostic proof.
  4. Simulate an old task write made obsolete by a later successful operation, a newer assignment generation, or a withdrawn review. Operator may explicitly supersede with an audit reason; automatic execution is refused where invariants cannot be established.
  5. Summaries scale for at least 1000 pending records, with optional detailed paging and no repeated full JSON payload; recovery remains operable at/above the existing limit with safe archive semantics.
  6. Concurrent clients/processes sharing a workspace cannot race retirement, replay, or archive of the same intent; atomic file handling and optimistic preconditions protect local state. Cover Linux and Windows sharing semantics where feasible. Run relevant Release client/server suites.
