Bound file reads, file search, and tree traversal before allocation

Priority: P2. Finding: JRV-2026-11-04. Review: docs/reviews/2026-11-07-deep-review.md (baseline e50c24af).

Problem

Unpaged read_file loads the entire file and constructs full response strings before the protocol size check. Line reads materialize selected lines; search_files recursively collects results before truncation and search_text traverses without independent work limits.

Relevant code

Client/Modules/ProjectBrowser.fs:685-725,767-856; Client/IO/Impl/FileOperations.fs:13-35; Client/SignalR/Client.fs:199-249; Common/Messages/AgentCommand.fs; Client.Tests

Implementation requirements

  1. Define separate limits for bytes read, lines returned, files/directories visited, wall-clock work, and bytes serialized. Enforce them before large allocations or traversal; do not rely on maxResponseBytes after full serialization.
  2. Provide efficient and predictable bounded pages/continuations for large text reads, preserving existing line-number/range semantics and UTF-8 correctness. A continuation should be snapshot-aware or clearly indicate content change instead of silently mixing versions.
  3. Implement lazy, early-terminating searches: maxResults should limit work where possible; traversal still needs independent reasonable work/deadline budgets and clear partial-result or continuation semantics.
  4. Preserve checkout containment, symlink rejection, search glob semantics and worktree routing. Clearly distinguish truncation/resource limit from an empty or complete result. Avoid introducing a large eager index.

Acceptance / verification

  • A 100+ MiB source file can be inspected page by page without allocating a giant managed string or constructing an oversize response; line-range read remains correct.
  • A large nested tree with maxResults=1 terminates according to explicit traversal limits and reports partial status when limits are hit, rather than walking and buffering the entire tree.
  • Tests cover UTF-8 chunk boundaries, small files, missing files, symlinks, path boundaries, glob filters, concurrent source changes, and generous backward-compatible defaults for ordinary files; Client Release suite passes.

Boundaries

Do not turn read_file into a binary-file transport; export_file remains its own mechanism.

Review the design and implementation; correct findings and re-review until accepted. Prefer long-term correctness to quick fixes.
