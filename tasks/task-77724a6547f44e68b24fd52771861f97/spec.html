Unify project/agent filter selectors and add Tab completion to the Jarvis TUI

Scope: Client-side TUI/filter logic only. Operator chose a deliberate breaking change to the display filtering syntax, not a server, MCP, Git-ledger, or persistent identity migration. No backwards compatibility layer is required for existing @project display filters. Do not modify the distinct protocol sentinel @global for workspace skills.

Intended user experience

  • #Wayfold filters by project; @Worker 1 filters by agent identity across projects; #Wayfold@Worker 1 and @Worker 1#Wayfold both select that agent in that project. #Wayfold@Worker matches all agents with names containing 'Worker' within Wayfold. Case-insensitive matching, unique project identity/aliases respected. Bare text still searches descriptive content where it previously did.
  • In Agents FilterMode, Tab autocompletes the currently edited trailing # project or @ agent selector from existing project summaries and agent rows. Prefix matching is case-insensitive; choose deterministic stable order and unique candidate names. Support spaces and multiword agent names such as Worker 1 and GUI Agent without requiring quoting. Preserve all earlier selectors/text when replacing current fragment. Completing #Way to #Wayfold or @Work to @Worker 1 must not change other filter terms. A previously selected project should narrow agent suggestions to agents actually in that project.
  • When multiple matches exist, Tab cycles through them (Shift+Tab reverse if easily supported by existing key handling); capture the original typed prefix and candidate set for a cycle rather than recomputing from the first completed candidate. Clearly show current candidate/count in the filter prompt if useful. Editing, Backspace, switching filter, Enter or Esc resets the completion cycle. No match leaves input unchanged. Enter applies; Esc restores the original filter. Empty selectors/partial selectors should not erroneously hide everything while typing.
  • The Activity view must display project tokens as #Project rather than @Project and support project-name Tab completion using locally known activity/project data. Do not claim activity entries have a canonical agent ID unless one is actually present; if absent, keep agent-specific @ selector semantics specific to the Agents view rather than guessing actors from messages. Keep the Activity export human-readable and consistent. The Agents view should support both project and agent selectors; avoid affecting Jobs filter or other unrelated mode hotkeys.
  • In AgentsMode both # and @ should enter/append the corresponding filter prefix without erasing an existing filter unexpectedly; / or f opens free-text filter. Update footer/in-filter help strings to mention #, @ and Tab. Tab must work only while editing filters and never trigger unintended mode actions.

Existing code / limits

Client/Modules/ActivityFilter.fs currently parses whitespace tokens and treats @ as project; AgentView.fs:274+ currently filters rows through free text and project aliases; ConsoleTui.fs has FilterMode at ~1895 and AgentFilterMode at ~1820, live filter state around ~108/120 and footer around ~488/~913, and shortcuts around ~1919/~2025. ActivityExport.fs renders projectToken. Existing tests in Client.Tests/ActivityFilterTests.fs and AgentView/ConsoleTui tests must be updated. ActivityEntry carries ProjectName but not necessarily canonical AgentId. Implement typed parsing, robust boundary detection for multiword selector names, no accidental project/agent identity conflation, and no network access in the Tab handler.

Acceptance

  1. Parser cases: project-only, agent-only, either-order combined, contiguous and spaced separators, casing, name with spaces, partial selectors, aliases/worktrees, bare text, malformed/empty selectors. Multiple filters combine sensibly (document AND semantics).
  2. Completion unit tests for zero, unique, multiple match/cycling, reversibility, edit reset, multiword agent names, project-constrained agent names, unchanged unrelated text, no candidate when snapshot absent, deterministic sort.
  3. UI key handling tests or a testable pure helper for Tab and Shift+Tab; no interference with Enter/Esc/Backspace; Activity and Agents help/documentation corrected. No changes to MCP, protocol @global, ledger or agent-state semantics.
  4. Full .NET 11 Client Release suite (and Server suite if shared code accidentally touched) passes, git diff --check; isolated worktree, exact committed source, independent review before Lead integration. Do not deploy unreviewed binary.
