Checkpoint diagnostics for read-only audit assignments

Source: Wayfold feedback f219c62389504ceeb4835b3cbc92ba78 (implicit-state-audit-desktop-runtime, State Audit Desktop). The agent reports Invalid Working checkpoint metadata on an unbound read-only attempt, although complete_agent_work could record the report.

Technical investigation

The current Client/Modules/ReviewWorkflow.fs checkpointAttemptWithSession path validates summary and nextAction up to 8192 UTF-8 bytes, and a nonempty evidence string up to 8192 bytes, before any remote transaction. A source commit is only verified if nonempty. Thus the observed generic validation failure may be oversized evidence rather than an unbound source. Investigate the actual captured request and do not conflate these preconditions.

Required behavior

  1. Produce field-specific errors for summary, nextAction, evidence byte count, malformed/unknown source SHA, invalid versions, and ownership/phase. State evidence limits in API descriptions and returned diagnostics, including whether truncation is permitted (default: reject clearly).
  2. Verify evidence-only checkpoint behavior with no source binding and an empty sourceCommit: preserve immutable summary, next action, evidence, generation, owner, and owner-reported evidence status. Do not manufacture a source commit or claim that evidence is independently verified.
  3. For genuinely large audit reports, retain bounded ledger records; specify and implement a separate bounded report/document reference path only if needed, rather than raising limits unboundedly or silently truncating proof.
  4. Maintain checkpoint immutability, idempotent UUID retries, correct Working ownership, version/generation rules, and compatibility with complete_agent_work. Avoid a second source-binding abstraction.

Acceptance

  1. Read-only Working attempt with no source binding successfully checkpoints short evidence and empty sourceCommit.
  2. Evidence exceeding the declared byte bound yields a precise field-and-limit error; summary and nextAction limits and invalid source each fail distinctly.
  3. Tests cover UTF-8 multibyte boundaries, stale assignment generation, oversized evidence, completion after checkpoints, multiple checkpoints, and audit history; Release suites pass.

No deployment without operator authorization.
