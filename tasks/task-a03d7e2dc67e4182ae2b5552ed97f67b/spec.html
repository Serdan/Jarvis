Problem

Reviewer and coordinator agents need to perform work without holding permanent placeholder implementation tasks. Today an agent becomes Working through an assigned task; role metadata alone must not imply activity.

Required behavior

  • Add explicit, agent-attributed start and yield/stop operations for taskless role work. Transitions must have named, typed lifecycle rules and version/generation checks. Role membership, ordinary reads, and arbitrary tool calls must not implicitly start taskless work.
  • Preserve independent ownership invariants: an implementation task has one exclusive active assignee, review requests retain exclusive reviewer claims, and taskless role work neither acquires nor releases either resource implicitly.
  • Allow a role-bearing agent without an assignment to be Working with role/activity context (and, where applicable, current claimed review), then yield to Parked when idle. Preserve the current client behavior of hiding Parked agents, showing actual Working agents, and clear unknown/stale last seen.
  • Define behavior for concurrent start/yield, role removal, a newly assigned implementation task, lost/replaced client sessions, admin inspection, restart and interrupted work. Avoid phantom Working, forged attribution or silent loss of claimed reviews.
  • Coordinate with the observer API task task-79b4fe205a86463184e5ff90b743e9d7 so observational calls cannot inadvertently start role sessions.

  2. Registering/assigning a role or reading its inbox leaves Parked unchanged; no automatic taskless activation.
  3. Task assignment and review claim exclusivity remain enforced; no double assignment or review ownership changes under role transitions.
  4. Concurrent and stale transitions are rejected safely; server/client restart and disconnected sessions preserve auditable canonical disposition.
