[P2] Optional review-dependent blocking with explicit reviewer queue

Goal: Let an implementation agent suspend its current attempt while awaiting the outcome of a specific review request, then resume normally when that review ends. The existing reviewer queue, independent claim process, frozen source snapshots, evidence and verdicts remain the sole authority for reviews. Blocking is optional and does not change reviewer workflow.

Design

  • Keep reviews first-class. Preserve submit_review, independent reviewer_inbox/claim_review, frozen source/ref and summary, claim release, review documents, Accepted/ChangesRequested/Withdrawn outcomes and owner feedback/acknowledgement. Do not wrap every review in a Challenge, auto-assign a reviewer, or substitute challenge subscriptions for the explicit review queue.
  • Optional waiting. An agent may submit a review and continue working, or explicitly block its active attempt on that exact review ID. Extend/reuse the durable challenge dependency waiting machinery with a typed prerequisite such as ReviewCompleted(reviewId) alongside ChallengeSatisfied(challengeId). Offer a clear MCP operation to block on review(s) (or extend the existing typed dependency API), rather than using fake challenges. The block transition releases the Working slot without requiring an additional yield_agent, preserves task/attempt ownership, generation and independent review data, and exposes the wait in the agent inbox.
  • Terminal outcome means actionable, not necessarily approved. When the review reaches Accepted or ChangesRequested, the awaited review prerequisite is complete; requeue the eligible blocked attempt to Ready (never Working) so the agent can read and act on the actual verdict. Withdrawn also ends that review wait and must wake the agent with its withdrawn outcome rather than strand it. Unclaimed, Claimed, and releasing a claim are not terminal and must not wake it. A verdict never automatically merges source, integrates, closes a task, or satisfies unrelated challenge conditions.
  • Reuse the dependency safety guarantees. Apply existing exact task/attempt/agent versions, assignment-generation checks, Git-ledger CAS, operation-ID deduplication, owner-slot availability, durable Eligible state, reverse indexing and later owner-slot reconciliation; do not create a second review-specific scheduler or polling loop. If dependencies can be mixed or multiple, enforce ALL for the explicitly chosen prerequisites and wake only after all are complete. If some prerequisites are already complete when a new wait is requested, handle the race deterministically rather than creating an unwakeable Blocked attempt. A fully completed set must not block.
  • Preserve independence. Reviews remain valid independently of an agent's execution state and task phase. Review claim/decision does not require a task to be Blocked. A blocked agent need not be the reviewer. A decision must not preempt an occupied or Parked owner, resurrect cancelled/closed/superseded attempts, or requeue stale generations. Existing UnacknowledgedFeedback and review-history retrieval remain the source of exact verdict and comments; show stable review identifiers/outcomes in ordinary inbox.
  • Scope: Implement after or in a conflict-free integration with the existing durable challenges feature, preserving its frozen independent review workflow. Make the smallest change to the canonical wait machinery that supports review references. Do not introduce a generic workflow engine, notification side effects, agent-launching logic, new review assignment policy or a parallel review queue.

Acceptance

  1. An agent submits a frozen review and explicitly blocks on its review ID. The request remains visible and claimable in the normal reviewer queue. An independent reviewer claims it without affecting the Blocked attempt.
  2. Reviewer records ChangesRequested. The blocked owner becomes Ready exactly once when eligible, sees the verdict and feedback in its ordinary inbox, and resumes to make revisions. Repeat with Accepted and with a withdrawn request. No implicit merge, task closure or source mutation.
  3. Submitting a review without blocking leaves the working agent undisturbed. Releasing/reclaiming a review changes only its independent queue state. Decisions for unrelated reviews do not release the blocked owner.
  4. Multiple dependencies (including review and challenge when supported) obey ALL. Partial resolution, stale review IDs, request already terminal at block time, cancellation, changes to attempt generation, simultaneous review-decision/block races, two clients, duplicate retries and restart never lose a needed wakeup or create duplicate assignments.
  5. An occupied or Parked owner stays unpreempted, with durable eligibility reconciled when its slot becomes available; cancelled, closed or superseded attempts cannot be resurrected.
  6. Focused race and negative-space tests plus full Client and Server .NET 11 Release test suites pass; submit a self-contained independent frozen review. No merge or deployment without operator approval.
