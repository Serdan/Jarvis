Investigate and eliminate intermittent JobManager environment-sanitization test timeout

Problem

The Client.Tests test startJob strips sensitive inherited environment intermittently fails with System.Exception: Job did not complete in time in JobManagerTests.waitForCompletion (reported around lines 208–217). The test has failed repeatedly during unrelated Release regression suites, including full runs after merges where focused tests succeeded. Determine whether this is a brittle test timeout, shared-resource interference, job scheduling/process behavior, or an actual product defect. Do not simply raise the timeout without investigating.

Investigation

  • Inspect the test, JobManager implementation, process spawning, polling and completion lifecycle, environment filtering, and cleanup logic.
  • Reproduce under Release with repeated isolated runs and under full-suite/parallel-test conditions; measure actual job-start and completion latency and identify timing/distribution or resource-contention factors.
  • Check whether the test can block on a child process, race cleanup, share state with other tests, or delay result publication after the process exits.
  • Preserve the security invariant: sensitive inherited environment variables must never leak into the child job process.

Required outcome

  • Fix any genuine concurrency or process-lifecycle defect found, or make the test deterministic with a justified, bounded synchronization strategy if the implementation is correct. Avoid arbitrary sleeps and hiding real failures with very large timeouts.
  • Keep diagnostics actionable: distinguish launch failure, process timeout, polling/result-publication failure, and environment-filtering assertion failure.
  • Add or adjust regression coverage for the identified failure mode, including concurrent jobs or test isolation as appropriate.
  • Run the focused test repeatedly, the related JobManager suite, and the full Client.Tests Release suite. Report evidence and any remaining intermittent failures.

Constraints

Prioritize correctness and maintainability. No unrelated refactors, weakening of environment sanitization, automatic integration or deployment. Deploy only with operator authorization.
