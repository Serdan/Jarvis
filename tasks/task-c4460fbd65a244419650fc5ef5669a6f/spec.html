Administrative correction of assigned Working agents

Feedback: 2bbaa4992f17436aa91914d7e006275e.

Problem

Lead needs to correct an accidental/stale Working state for another agent without impersonating that agent or manufacturing a checkpoint. The existing unassigned set_agent_state cannot do so; recover_agent_assignment changes generations unnecessarily, while yield_agent misattributes an administrator's action.

Required behavior

  • Expose a distinct administrative command accepting actor ID, target agent ID, exact task/attempt identity, expected task/attempt/agent versions and generation, and a nonempty reason. Restrict to an existing assigned Working attempt; transition only execution to Ready.
  • Preserve task ownership, attempt identity, source/baseline refs, assignment generation, checkpoint/evidence, review claims, pending integrations and notifications. Do not fabricate a worker checkpoint or last-seen activity for the target.
  • Write an auditable immutable event with actor, target, reason and before/after state. Distinguish administrative correction from normal agent self-yield in all inspection APIs.
  • Use atomic optimistic concurrency so a stale correction cannot override recent genuine activity or an agent's own yield. Ensure authorization follows documented operator/admin semantics without allowing arbitrary target impersonation.
  • Integrate conceptually with side-effect-free observer operation task-79b4fe205a86463184e5ff90b743e9d7; no requirement to wait for that feature to land.

Acceptance

  1. Lead corrects erroneously Working Architect to Ready with exact versions; assignment/generation/checkpoint and target last seen remain unchanged.
  2. Concurrent genuine work, wrong generation/version, missing task, unauthenticated actor or different current status fail without mutation.
  3. Self-yield_agent continues to produce its ordinary worker-attributed checkpoint; administrative audit is unambiguously different.
  4. Replay by operation ID is idempotent. Relevant ledger/API/client Release tests pass.

Do not deploy without operator approval.
