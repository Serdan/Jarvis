Account-global AGENTS.md across machines

Feedback: 7bf163e39b6c4c219743c4357677a795.

Goal

Provide one stable, authenticated account-wide instruction document visible to all clients and projects, independently of local workspaces or current task ownership.

Design

  • Persist one UTF-8 AGENTS.md per authenticated user account on the single-instance Jarvis server filesystem (for example under its private user-data directory), with strict account/path isolation, safe file modes, bounded size, atomic replace and optimistic version/hash precondition. The account ID must be resolved from authenticated identity, never from a caller-supplied path or account ID. No database or distributed coordination.
  • At server startup, load the existing per-user instruction files into an in-memory account-keyed snapshot before serving agent instruction requests. Serve instruction delivery from that snapshot; an authenticated conditional update must atomically persist the new file and refresh the in-memory value only after a successful durable write. On restart, reconstruct the snapshot from the filesystem. Missing, empty, malformed and unreadable records must remain distinguishable; a load failure must not silently turn a configured policy into an empty instruction.
  • Expose authenticated read and conditional update operations with conflict reporting, exact version/hash and clear missing/empty document semantics. Never let an agent supply another account ID to read/write that account's instructions.
  • Prepend the account-global document to the workspace/project/directory instruction hierarchy as a distinct level with explicit precedence. Preserve existing relative path-keyed AGENTS.md representation for repository files, and coordinate presentation with task-0b8cf504e4ac41129d581fc6629021c4 and role/per-agent instructions task task-42e64eb74fef43588d8c64f656e12088.
  • Deliver on an agent's next applicable working turn/fetch, using safe cache invalidation and conservative redelivery on client reconnect; never silently omit instructions because server state is unavailable. A missing or unreadable global file must be distinguishable from a successfully empty file.
  • Keep actual task, challenge, notification and agent ledger authority unchanged. Avoid turning the server into a persistent workflow store.

Acceptance

  1. Update from machine A; a newly started agent on B sees the same document before its local AGENTS.md, with documented precedence and no duplicate payload on each repeated tool call.
  2. Two concurrent edits with the same expected revision yield exactly one committed update and one explicit conflict; interrupted writes leave complete old or complete new content.
  3. Tests cover account isolation, unauthorized access, path traversal, oversized/invalid input, fresh installs, server-start preload, successful write/cache update, process restart reloading from disk, missing/unavailable server file, client reconnect and instruction layering; Release suites pass.

Do not deploy without operator authorization.
