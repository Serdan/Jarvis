Protect local activity history and bound history reload costs

Priority: P2. Finding: JRV-2026-11-06. Review: docs/reviews/2026-11-07-deep-review.md (baseline e50c24af).

Problem

ActivityLog creates the activity directory, JSONL logs and agent-seen.json with inherited filesystem permission defaults. Command activity can include paths, arguments and error details. LoadRecent scans all retained files before taking the requested tail.

Relevant code

Client/Modules/ActivityLog.fs:30-34,96-105,119-121,152-205; Client/Modules/OAuth.fs:278-305; Client.Tests/ActivityLogTests.fs

Implementation requirements

  1. On Unix, establish and repair private permissions on the activity directory (0700), JSONL files (0600), agent-seen state (0600), and temporary files. On Windows, document/use user-private ACL behavior where necessary. Verify/reject unsafe symlinks before opening or replacing local files.
  2. Handle existing installations safely: repair weaker modes without silently deleting history, preserve append/rotation and retention, and report useful diagnostics rather than silently masking permission failures when action is required.
  3. Use atomic persisted last-seen snapshot replacement with correct staging modes and safe cleanup. Ensure the activity writer cannot follow attacker-provided links; avoid leaking secrets into exceptions/logs.
  4. Bound LoadRecent for large retained histories, using simple reverse/tail traversal or a bounded index rather than full retention scans. Preserve latest-per-activity semantics including normalization of interrupted entries.

Acceptance / verification

  • Tests under deliberately permissive process umask establish private directory/file modes; prior loose modes are repaired, symlinks are rejected, and rotation/retention remain correct.
  • LoadRecent(20) returns the correct recent distinct activities without scanning/parsing the entire history for a large log corpus; documented performance test verifies growth behavior.
  • Platform-specific file tests and full Client Release tests pass.

Boundaries

No need for database-backed activity logging or indefinite retention.

Review the design and implementation; correct findings and re-review until accepted. Prefer long-term correctness to quick fixes.
