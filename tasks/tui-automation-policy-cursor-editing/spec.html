Make the TUI Automation policy editable in place

On the deployed #Jarvis Automation panel, the user could not move the text cursor to change automation=off to automation=on. The current workflow forces clearing and retyping the entire draft, which can drop configured capacity limits.

Support moving the cursor and editing the existing multiline policy in place. At minimum support horizontal movement and movement between lines, with insertion and deletion at the cursor and a visible caret. Reuse the existing editor only where that preserves its current behavior. Keep authenticated policy save/readback, validation and stale or uncertain write reconciliation. Preserve existing caps when the user edits only the Automation line.

Exercise the actual key handling with an off draft containing total and role caps. Change only the flag and verify the saved policy retains every cap. Cover cursor boundaries across lines and preserve existing save, reload, copy and cancel behavior. Independent review before release. This follow-up does not block the current #Jarvis trial.
