**Priority:** review-blocking evidence gap (tests/docs only). **Frozen source:** `5e1798003064df3ff23017f42aebb74d89817739`.

- `Server.Tests/OriginalGitSourceObjectHandoffTests.fs:118-119` asserts that an **empty** unrelated bare repository has no `managedRef` and a nonexistent ref has no advertisement. This does **not** test rejecting the wrong original when it exposes the *same pinned ref and OID*, the important repository-identity substitution attack. - `:123-130` deliberately simulates an acknowledgement loss with a constant `false`; it does establish that the remote advanced while a cached object remains, **not** that a durable original effect receipt/reconciliation state machine correctly treats unknown outcomes.
- The task spec explicitly asks for negative tests for rollback/pre-STOP lost effects and replayed original/stage UUIDs. Neither appears among these three tests. The design document `docs/design/work-original-git-object-handoff-evidence-2026-11-19.md:35` correctly classifies them as future failure states, but documentation is not an executed negative gate. Its line 26 currently overstates what the wrong-original/wrong-parent tests prove.

**Required correction:** Within the owned disposable test/docs files, make negative tests genuinely adversarial where a real verifiable seam exists: e.g., put the same candidate/ref in an unrelated remote and test the *independently pinned repository identity*, and supply a plausible wrong expected parent against a meaningful verifier/decision (not self-parent comparison). Keep default-off and avoid inventing production `Verified`. For missing receipt/high-water and UUID replay seams, either add a **clearly labeled non-authoritative contract test** with actual rejection assertions and state its evidentiary limit, or explicitly classify the cases as **not executable until the named enforcing producer/reader implementation lease** and amend test/exit claims.
