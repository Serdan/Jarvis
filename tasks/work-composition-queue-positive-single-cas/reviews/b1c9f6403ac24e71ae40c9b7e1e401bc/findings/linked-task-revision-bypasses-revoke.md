# P1 — A valid linked-task revision bypasses automatic WQ02 revocation

**Frozen source:** `656e368045e6200f3838e0e6e1b5ab882b6a5718` (base `3458224ce3bff9141b05a7891148098db4900053`).

**Source evidence.** `Client/Modules/WorkCompositionGitLedger.fs:134-146` decides whether to revoke an installed WQ02 stage by searching **only the post-mutation graph** for `unit.Spec.LinkedTaskId = Some stage.SubjectId`; it gates only a matched unit's cancellation or unmet hard prerequisites. `Server/WorkComposition.fs:281-285` allows a valid `WorkCompositionMutation.Revise` to replace the entire `WorkUnitSpec`, including `LinkedTaskId`, while incrementing the spec version. `WorkCompositionGitLedger.execute` at lines 172-206 writes a graph-only transaction when `queueRevocations` returns `[]`.

**Concrete failing path (source-level):** Starting from the test's successfully held and released original planning stage (`SubjectId = "delivery-task"`), issue an ordinary graph `Revise("dependent", currentSpecVersion, newValidSpec)` where `newValidSpec.LinkedTaskId = Some "replacement-task"` and the independently accepted prerequisite is unchanged. The old WQ02 stage is still installed/Available, but no unit in `nextGraph` links to `"delivery-task"`. `broken stage` is false; no WQ02 record is written in the graph CAS. Thus the obsolete original WQ02 stage remains Available at the new canonical head despite the bound graph unit's spec/task identity changing. The optional `revokeOnGraphMutation` path at `Client/Modules/WorkCompositionQueueTransaction.fs:253-265` also checks only cancellation/unmet prerequisites, not changed spec/linked-task identity.

**Impact:** Fails the task's requirement that changed graph/spec/source binding revoke or block stage eligibility with no graph/WQ02 contradiction. Mutations that drop or rewire hard prerequisites also need an explicit binding/invalidation policy; merely evaluating current post-mutation prerequisites is insufficient for an already authorized stage.

**Requested correction:** Persist or reconstruct a trustworthy immutable stage-to-composition-unit **and spec/version** association, compare the original and proposed graph, and atomically revoke or fail closed on a changed/missing binding, spec, parent, linked task or prerequisite closure. Add a two-clone original-ledger regression exercising dependent `Revise` to a distinct `LinkedTaskId` after release, asserting the same Git mutation contains both graph and queue paths and that the old stage is no longer Available. Include an unrelated-revision control and idempotent replay.

**Verification note:** Independent .NET 11 Release `WorkComposition` tests passed 12/12, including 3/3 new transaction tests, but none covers this graph revision path. This finding is based on direct control-flow inspection; the exploit path was not separately executed as a new test.
