# P1: Effect journal digest is not bound to the events

At frozen fcf2bb18f03132751c2f5b6922c3532d7c809157, `checkEffectJournal` checks only that `DurableDigestSha256` is syntactically a SHA-256 and equals `RemoteDigestSha256`. It never computes a canonical digest of `Events` or verifies an authenticated receipt that binds those event bytes, their outcome, target and high-water to the remote anchor. A capture can therefore retain the same matching digest strings while changing an event from `Unknown` to `NoExternalEffect` or to `Observed` with any syntactically valid commit. If the operation ID and request/result digests still match a project operation, the remaining checks pass. The two reads can return the same corrupted capture, so reinspection does not detect this. The positive fixture explicitly uses a label-derived digest rather than a digest of the event data; the corrupt test only changes one of the two digest labels.

This defeats the stated fail-closed proof of pre-STOP unknown effects even for an otherwise authenticated reader that faithfully returns an inconsistent/corrupted journal. Bind a canonical, domain-separated serialization of the complete target, ordered events (including outcome and observed commit), and high-water to a verified remote anchor; reject mismatches. Add a negative test that mutates an event while leaving both digest fields identical, plus target/high-water binding coverage. The upstream authenticated reader and durable remote audit remain unimplemented and cannot be inferred from fixture success.
