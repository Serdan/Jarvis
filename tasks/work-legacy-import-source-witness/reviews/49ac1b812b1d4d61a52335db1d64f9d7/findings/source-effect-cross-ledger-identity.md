# P1 — source-effect journal can verify the wrong original ledger epoch

**Frozen review:** `49ac1b812b1d4d61a52335db1d64f9d7` at `4f562bcad458f0dcd8ac2cc1a438cd475673b363` (base `aa2e46ff2927b8e9fd0af25204377c299f2ec576`).

In `Server/WorkLegacySourceWitness.fs`, `checkEffectJournal` (approximately lines 200–206) validates a SourceEffect target's shape, account, project and repository ID, but **never requires its `LedgerId` or `LedgerEpoch` to equal the enclosing original project ledger** (nor does it compare the approved remote fingerprint). `OriginalGitPublisherAdmission.validateTarget` only validates syntax/scope; it explicitly is not an authenticated remote inventory. The new `effectJournalDigest` hashes the supplied `journal.Target` rather than independently pinning that target to `ledger.Target` / the C0/C2 fence. The remote-digest equality check (approximately lines 207–237) and `OriginalBarrier.ExactTargets` comparison (approximately lines 440–450) can therefore pass for a mutually self-consistent but wrong ledger source-effect target.

**Independently reproduced, not just theorized.** Archived exact frozen commit into an isolated temporary directory (no author's source/branch edited), appended one disposable NUnit negative test, and ran .NET SDK 11.0.100 `dotnet test Server.Tests/Server.Tests.fsproj --configuration Release --filter "FullyQualifiedName~WorkLegacySourceWitnessTests"`. Start from the valid two-project/one-account fixture; for project one replace only the effect journal's `Target.LedgerId` with a fresh GUID and `Target.LedgerEpoch` with 5 while leaving the enclosing `ledger.Target`, C0 inspection, C1 SQLite receipt and C2 `Fence.Binding` unchanged. Recompute both journal digest fields using the new canonical `effectJournalDigest`, update the synthetic `OriginalBarrier.ExactTargets` to reflect the wrong effect target, and have both authenticated-reader fixture calls return this same capture. **`WorkLegacySourceWitness.capture` returned `Ok`**. The added test failed with: `Accepted source-effect witness from unrelated ledger ID and epoch despite matching self-consistent digests/barrier.` Six original witness tests passed; the seventh (new negative test) failed as expected. This demonstrates a cross-ledger false-positive `Verified` boundary even after the prior event-payload digest fix.

**Required correction:** Reject SourceEffect receipts unless their account/project, ledger ID, ledger epoch, canonical repository ID and approved remote fingerprint match the enclosing original ledger's authenticated identity and STOP/fence provenance. Do not accept a self-echoed remote target list as an independently verified inventory; authenticate the specific SourceEffect ref/remote anchor under the original enforcement domain. Consider also binding `ledger.Target.CanonicalRepositoryId` to `fence.Binding.TrustedRemoteId`. Add fail-closed negative regressions that recompute matching digest labels and barrier lists while substituting a valid differently scoped ledger/epoch, remote fingerprint or source-effect ref. Keep actual source reader and independent durable remote effect anchor explicitly unimplemented until their own reviewed evidence exists.

The previously reported event-content/digest mismatch has been corrected at this frozen commit; this is a **distinct P1 identity-binding defect**. Even a passing test suite is not production authority. Live migration, writer retirement, Scheduler/dual-writer operation and cutover remain HOLD.
