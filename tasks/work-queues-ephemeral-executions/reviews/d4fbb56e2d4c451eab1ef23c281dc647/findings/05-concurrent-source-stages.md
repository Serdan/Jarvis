# F05 — P1 — Per-item claim uniqueness does not serialize related source mutations

**Frozen source:** lines 43–56, 108–110, 120–132, 144–172, 210–221, 296–305.
**Related existing contract:** docs/specs/orthogonal-agent-state.md lines 67–73 currently preserves one current implementation attempt/owner per task while leaving multiple independent reviews possible.

**Finding.** `one current claim at most` is enforced per **work item**, not per task/source context. The proposed producer rules make each ChangesRequested verdict a new correction stage. A task can legitimately have multiple independent reviews of different frozen commits. Two ChangesRequested events (or readiness and correction events racing) could then create two Available work items with the same mutable task/source context. Two workers atomically claim different items, both win, and both modify or publish incompatible follow-up snapshots. Per-item CAS and clean isolated worktrees do not by themselves define which correction advances the authoritative task implementation stage; they merely isolate files while allowing divergent work.

**Required design resolution.** Define stage supersession/dependency and a canonical exclusivity key for *source-writing* work on the same task/source lineage (or an explicit branching/merge policy allowing parallel tracks). On publishing or claiming a correction item, compare the task's current stage generation, source baseline, existing correction demand, and expected reviewed SHA. Conflicting items should be coalesced, serialized or explicitly branched, without forbidding multiple independent review requests for the same task. Explicitly separate review-item concurrency from source-writer concurrency and clarify what happens to stale correction items after a newer accepted revision/integration. Never let an older correction silently overwrite a newer implementation baseline.

**Required tests.** Two independent reviews for one task both ChangesRequested; simultaneous worker claims cannot mutate the same canonical implementation lineage without an explicit branch/merge contract. Concurrent Lead readiness and correction publication converge to one actionable source-writing stage (or documented independent lineages). Stale review feedback is preserved for audit but cannot regress the current source tip. A reviewer decision and task-stage supersession racing produce deterministic, replay-safe results.
