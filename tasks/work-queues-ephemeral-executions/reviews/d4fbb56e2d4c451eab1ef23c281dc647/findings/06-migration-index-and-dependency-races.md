# F06 — P1/P2 — Migration and derived-state race cases need explicit gates

**Frozen source:** lines 59, 65–74, 112–130, 160–172, 223–229, 263–292, 302–313.
**Related existing contracts:** docs/OrchestrationMigration.md; docs/ManagerHeartbeat.md; docs/ExecutionScheduling.md.

**Finding A (P1: migration claimed reviews).** Phase migration step 2 drains Working assignments and uncertain launches, but independent reviewers are *not* necessarily in task assignments. Step 4 proposes converting already Claimed reviews into work items without specifying the matching activation. Marking such an item Available risks a second reviewer; marking it Claimed without a live activation strands it. Also inspect source-writing jobs, pending Git-ledger write intents on every client, integration submissions awaiting verification, and old Manager journal reservations before changing writer schema. The old client cannot continue mutating shared records after conversion.

**Required migration rule.** At an exact inspected ledger head, enumerate claimed/unclaimed/decided reviews, all in-flight review activity, local pending-intent journals, integration submissions/receipts, challenge conditions, mutating jobs, and cross-device scheduled launch states. Refuse cutover until claims/operations with unknown outcomes are explicitly reconciled or have a documented generation-preserving conversion. Fence incompatible writers with protocol/schema handshake before the first new-format commit. Verify the mapping is injective (one logical work stage -> one work ID) and failure leaves old schema authoritative. Clarify conversion of historically deferred/blocked attempts with no current owner and older source bindings.

**Finding B (P2: dependency publication race).** A `BlockWork` can race with completion of its last challenge. If wake is processed just before the block commits, a naive event-driven index can miss the wake forever. Define checking dependency versions/terminal states *when block commits*, and a watermark-based reconciler for missed wake events. For partial/complete index coverage, a single migration marker is insufficient after new events; specify a verified producer high-water mark/shard coverage relative to the current ledger snapshot. Failure must report incomplete coverage, not zero work.

**Required tests.** Claimed independent reviewer active at cutover; client pending-intent retry across migration; unknown submitted integration and scheduled Manager launch; partial conversion crash and old-client write; multiple challenge dependencies with satisfaction-before-block, satisfaction-during-block, and wake-after-restart; stale/partial queue shard while source producer advances. Check that old checkpoints, review ref/blob OIDs, findings, exact integration SHA, source baseline, and operation receipts remain readable.
