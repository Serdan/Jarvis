[Architecture epic] Durable work queues and ephemeral agent activations

Architecture to implement

  • Replace persistent worker-to-task assignments, Waiting/NeedsWork and Parked availability with durable work items and disposable role-based activations. Retain tasks and their audit/spec/checkpoint history.
  • Provide durable role subscriptions for planning, implementation, review, integration and relevant challenge follow-up. Subscriptions are routing conventions, not agent permissions; all agents under the owner's account share account-level permissions.
  • Each launched execution claims an eligible work item atomically. Checkpoints, final yield, block and completion operate on the work item/activation, not permanent worker IDs. Yield must atomically checkpoint and free unfinished work. Another worker/session can continue.
  • Manager launches bounded role sessions from eligible queue depth; each claims within the session. Retain durable one-shot browser submission and no-blind-retry uncertainty handling, 5-worker/3-reviewer limits pending operator revision, and terminal session evidence before reusing capacity.
  • Generalize existing canonical frozen reviews, integration submissions, challenge dependencies and Lead planning into queue producers/subjects. Preserve exact accepted source SHA, immutable evidence, and idempotent source integration.

Delivery plan and gates

  1. Independent review and acceptance of the proposed spec. Resolve design ambiguities before code.
  2. Build pure planner fixtures and canonical Git queue/claim/activation/checkpoint lifecycle; write two-client atomic-CAS, stale-turn and idempotence tests.
  3. Implement role subscriptions and deterministic task/review/integration/challenge producers, including complete index coverage checks and blocked wakeups.
  4. Refactor Manager/browser bootstrap from persistent worker names to role demand and per-execution claims; verify launch uncertainties and no duplicate active sessions.
  5. Migrate existing task attempt ownership, old checkpoints, review claims and UI/TUI projections with an explicit checked conversion, preserving history.
  6. Rehearse disposable conversion and rollback, .NET 11 Release and Node tests, then separately seek operator authorization for matching production client/server update and controlled activation.

Non-negotiable acceptance

  • Five available tasks + five worker slots allow five unique claims across arbitrarily labeled sessions; ten simultaneous claims across two clones still yield at most five winners.
  • Yield preserves source and checkpoint and makes unfinished work available to a different worker with no ownership-transfer command. Obsolete activations cannot mutate canonical work state.
  • Claim resolution alone never proves reviewer execution ended; no duplicate reviewer session may be launched until terminal yield/verified recovery.
  • ChangesRequested requeues correction once; Accepted produces a single exact frozen-SHA integration item; ambiguous merge/push is reconciled before retry.
  • Challenges retain durable dependencies, blocked work releases execution slot, and wakeup is idempotent. Failed/unknown queue index coverage must not read as empty.
  • All existing canonical records and history survive conversion. Main/source deployment is a separately authorized operational step.
