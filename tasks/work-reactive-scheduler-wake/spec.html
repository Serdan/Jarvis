Work Scheduler — reactive wake and bounded reconciliation

Part of the operator's explicit Agent => Work replacement and non-agent Scheduler mandate. WQ02 durable Work/dependency states, WQ04 blocking-first readiness and WQ08 cross-project planner already exist on main as reviewed default-off primitives. The missing independent slice is the **reactive non-model wake/reconcile loop**: Work with unmet dependencies consumes no model slot; committed dependencies or capacity-release events make eligible Work visible to the scheduler without waiting for a human/persistent Lead. Worker4 independently owns composable-work-units graph semantics; Worker10 owns the WQ08 default-off admission/one-shot executor; Worker12 owns Work-native API. Do NOT duplicate those.

Scoped implementation

Implement the smallest typed, default-off scheduler wake coordinator against existing verified state readers and injected planner/admission callbacks. Normalize triggers from Work/dependency review/acceptance/integration transitions, capacity-release and new Work creation into a bounded idempotent reconcile request. Re-read canonical Git authority before every decision; do not persist scheduling truth on the Jarvis server or invent an extra queue. Provide a simple invocation/restart seam, coalescing and bounded retry/reporting when Git changes concurrently, and an actionable Unknown/NeedsAttention result for unavailable evidence. Leave the actual claim/admission/dispatch effect in a supplied WorkExecutor port to avoid overlapping Worker10's changes.

Prefer one new module and focused hermetic tests; no changes to Worker10's executor, Worker4 graph, Worker12 authenticated API, Worker1 read-only host preview, existing WQ02/WQ04 contracts or production registration unless a concrete gap makes a narrow reviewed fix unavoidable. Existing source-of-truth and operation-ID semantic replay are mandatory, but keep design proportional.

Minimum acceptance

  • Fully specified Work with two unsatisfied hard prerequisites remains dormant with zero execution slots; one prerequisite accepted/integrated does not dispatch; second committed prerequisite triggers exactly one eligible callback; a newly created child Work unit follows same rule.
  • Two concurrent/coalesced wake signals for the same updated head do not cause duplicate callback effects; at cap=0 or unknown account proof Work stays queued; capacity release can wake it once verified.
  • Restart/resubscribe does not depend on transient server cache; subsequent reconcile from durable heads yields the same readiness and exposes any uncertain original operation.
  • Realistic disposable Git backed tests for bound read ports plus fake-only executor; .NET11 Release, independent task-bound frozen review, exact source SHA and Lead-only integration. Report which live event subscriptions/production deployment remain disabled.

Do not enable unattended production scheduling or real browser dispatch, migrate epochs, restart services, use GitHub-hosted Actions or Codex through Jarvis. Independent work must preserve WQ08 host/admission ownership boundaries.
