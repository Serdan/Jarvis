# P1 — Authorized-project filtering cannot scope stage data; project-ID collision leaks another project's Work

**Frozen source:** `861d979406112fedb76cf4f966262e7e47e8ac5c`
**Paths:** `Client/Modules/WorkStatefulContracts.fs` (`WorkNode.ProjectId` versus `WorkStage` without any `ProjectId`); `Client/Modules/WorkStatefulProjection.fs:330-341,365-408`; current test `Client.Tests/WorkStatefulProjectionTests.fs` `scopedServerSnapshotFailsClosedWithoutLeakingOtherProjectTitles`.

For an `AuthenticatedServer` snapshot, `renderAt` applies the authenticated project allowlist only to **nodes**. It then includes every stage satisfying `Map.containsKey stage.NodeId nodes`, using the node ID alone. `WorkStage` has no project identity field to verify against the authenticated scope. A stage from **unauthorized project B** whose `NodeId` equals an allowed project A node ID is consequently rendered as if it belonged to A, disclosing stage ID, queue, claim/launch identity, review SHA, integration SHA, priority and readiness. This also mishandles legitimate same-named node IDs across multiple authorized projects (the selected-node dictionary rejects them globally).

**Concrete negative fixture:** Start with the existing authenticated A-only scope `AllowedProjectIds=set [ "p" ]`, and a visible A node `Id="f"; ProjectId="p"`. Include a `WorkNode` `Id="private-root"; ProjectId="other"` (filtered out) and a stage from project `other` with `NodeId="f"; Id="confidential-review"; Review=Accepted <frozen SHA>; State=Claimed <launch>`. Because the stage record has no `ProjectId`, `projectStages` includes this private stage, and the resulting `Dashboard.Stages` shows it under A's node path. The existing scope test only verifies that a private node title is hidden and does not exercise stages.

**Required:** Add canonical project identity to each stage (or an equivalent globally unique composite node key that is verified against the authenticated project set), match stage-to-node on `(ProjectId, NodeId)`, and use composite keys consistently for multi-project maps/duplicate detection. Fail closed if the stage identity or its node binding is ambiguous. Add negative tests for cross-project colliding node IDs and an authorized multi-project view with identical local node IDs. H0 has no live mutation endpoint, but its projection is already claiming authenticated read-scope safety; leaking read data is a real correctness/security defect in this frozen contract.
