# P1 — safe source yield ignores unresolved mutating jobs and unknown push journals

**Frozen SHA:** `4f0ac4df3f3f437501c8da054c262706ec3f5e64`.

**Evidence:** `Client/Modules/WorkQueueGitLedger.fs:278-329` implements `verifySourceHandoff` using trusted remote ref/SHA, local HEAD, `git status`, commit existence and ancestry. It reads **no mutating-process journal, unresolved original push operation, lease-owned worktree effect state or confirmed process termination**. `YieldSource` invokes this verifier at `:767-773` and then commits an Available work stage with a terminal old launch via `Server/WorkQueueContracts.fs:1458-1524`. Free-form `TestEvidence` in `SourceCheckpoint` is nonblank text only; it is not evidence of job reconciliation. The new test `MissingRemoteWipDirtyCheckoutAndUnknownJobRemainClaimedRecoveryBlocked` (`Client.Tests/WorkQueueGitLedgerTests.fs:1117-1147`) manually calls `MarkSourceRecoveryBlocked` after choosing a reason; it does not stage an actual unresolved mutating process/push and verify that `YieldSource` fails without that self-report.

**Failure:** If a mutating child process or uncertain Git push is still running while `HEAD`, status and remote WIP tip happen to be clean/matching at the instant of verification, `YieldSource` can succeed. The old claim is then requeued for another session even while the old process can write/push later. A role's voluntary `MarkSourceRecoveryBlocked` cannot substitute for independent gating; source-writing exclusivity needs to cover outstanding externally authorized side effects, not just project CAS mutations.

**Required correction:** Before publishing an Available source stage, reconcile every mutating job and original push journal associated with the exact worktree, launch, source ref, claim generation and effect operation ID. Hold `SourceRecoveryBlocked` (retaining claim/token/worktree fence) on running, unknown or nonterminal effects; fail closed if coverage is incomplete. Add deterministic two-clone tests with an explicitly pending mutating job / unknown push that initially leave the checkout clean; verify normal `YieldSource` is rejected, then recover only after journal-terminal evidence or exact original-effect proof. This is an acceptance blocker under source safety §9, not merely a desirable later integration.
