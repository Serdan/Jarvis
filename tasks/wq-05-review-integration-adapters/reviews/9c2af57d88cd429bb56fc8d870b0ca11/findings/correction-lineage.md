# P1 — ChangesRequested correction is not tied to the reviewed current source lineage

**Source:** `Client/Modules/WorkQueueReviewIntegrationAdapter.fs:166-206`; fixture `Client.Tests/WorkQueueReviewIntegrationAdapterTests.fs:212-246`.

`planCorrection(project, queue, review, source)` requires `review.Status = ChangesRequested`; `source` to be the exact completed implementation stage in the local map; and `source.SourceLineage.TaskId`/`TargetRef` to equal the review's task/target, with syntactically valid base SHA. It **never joins** the review's `AttemptId`, `SourceVersion`, `SourceSha`, `SourceRef` or frozen `ReviewRef` to the completed implementation stage's canonical source attempt, lineage/generation, or exact reviewed commit. It doesn't identify the *current* source-stage generation for the task from the project ledger.

**Counterexample from the predicate:** Project contains completed implementation stages S1 and S2 for the same TaskId and TargetRef but with different LineageIds (e.g. superseded owner attempts). A ChangesRequested review of S1 is admissible with S2 passed as `source`; the predicate cannot distinguish them. The duplicate scan only matches the chosen LineageId, so a correction from the wrong lineage can be constructed, and distinct source stage generations can yield distinct correction IDs for one review. The current positive test contains only one completed source lineage; it never tests S2 or mismatched reviewed source.

**Required:** Bind canonical review ID/attempt/reviewed SHA to exactly one current source-lineage stage/generation under an authoritative high-water/versioned snapshot. Refuse missing or ambiguous join, stale source generation, wrong lineage, duplicate correction across lineages for the same review, and a completed alternative source stage that is newer than the reviewed source. Add two-client CAS negatives where the source stage is replaced or review verdict arrives after a newer attempt. If existing `SourceLineage` does not carry enough identity, add an explicit source-review linkage contract for the WQ-04 producer rather than inferring it from matching task/target alone.
