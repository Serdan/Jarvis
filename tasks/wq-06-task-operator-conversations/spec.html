Scope

  • One immutable append-only conversation substrate whose recipient is Task(projectId,taskId) or Role(projectId,roleId), including durable Role(Jarvis,Lead) messages even when no Lead execution exists. Preserve other canonical review/integration/planning subject types.
  • Operator posts a message with stable message ID and reply-to. In the same Git-backed transaction, create one verified pending message-handler work-demand projection on the Task/Role queue, not a new agent-addressed inbox or general event bus.
  • First eligible execution to act on that task/role wins atomic ClaimPendingSubjectMessages CAS and receives ordered messages plus cursor. Reading alone does not consume messages; other role instances may view but cannot double-handle a claimed message. A live role agent may take an ancillary message handling lease while retaining one primary work claim, without stranding other admitted role-message launch demand credits.
  • CompleteSubjectMessageHandling commits reply/handled evidence with exact operation IDs and durable conversation history. Release/recover unfinished handler lease on yield, stop/stall or terminal execution, supporting redelivery to another UUID without duplicate canonical answers.
  • Retain challenge-backed operator questions/dependencies and explicit approval/task-spec mutation. Task/Role chat never automatically unblocks tasks or authorizes unrelated work. STOP alerts remain directed to individual agent UUIDs via the existing response-alert system, not Task/Role conversation.

Acceptance

  • Operator messages Role(Lead) while no Lead is running. Manager sees compatible queued demand; first eligible Lead execution handles and responds; another Lead UUID later reads the full thread. No persistent Lead assignment, fanout or Worker-N recipient is required.
  • Concurrent same-role agents race handling the same message: one CAS winner; task-stage agents obey the same rule. Passive reads never mark Handled.
  • Handler stalls or yields before response: message returns to Pending with immutable history. Lost acknowledgement after durable reply recovers original reply receipt rather than reposting.
  • Already-active Lead with other work can take ancillary role message only when compatible rematching preserves outstanding launch-demand credits; no extra primary task claim or global capacity bypass.
  • Task-block/challenge answer races, incomplete queue index coverage, per-session STOP alert separation and Release regression suites pass.
