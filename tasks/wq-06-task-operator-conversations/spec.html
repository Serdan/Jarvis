Scope

  • Add immutable messages on canonical task/subject: Note, Question, Response and Decision with reply-to, actor/launch attribution, version and bounded continuation cursor.
  • Expose operator attention list derived from verified index coverage; operator answers address a task/question, not Worker N inbox; preserve historical agent notifications read-only.
  • For blocking questions link a response to one canonical Challenge condition and BlockWork dependency with atomic CAS on answer/satisfaction; nonblocking messages cannot change task scope or approval.
  • Ensure a new execution retrieves prior questions/replies and source context after another session yields; project-wide questions use planning/decision subject.

Acceptance

  • Worker A posts question, yields, Worker B resumes with same readable history; operator can reply while no Worker is running.
  • Two concurrent responses satisfy challenge once; final dependency satisfaction requeues exactly once even racing BlockWork, restart or stale indexes.
  • Informational message never implicitly revises task/accepts review/authorizes unrelated work; UI attention list excludes answered/superseded questions.

Out of scope

Do not replace account permission or operator consent protocols; no generic chat/event-bus subsystem. Implement only in isolated worktree; use .NET 11 Release and relevant Node tests, frozen independent review and exact-reviewed-source integration. No Codex through Jarvis.
