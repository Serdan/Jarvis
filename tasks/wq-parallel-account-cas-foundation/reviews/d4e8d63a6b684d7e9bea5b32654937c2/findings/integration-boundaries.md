# Integration boundaries (advisory; nonblocking for this frozen inert foundation)

**Severity:** Advisory, not a finding that reverses the corrected F01/F02 race contracts.

1. **WQ-02 terminal proof is not implemented by this source.** `Client.Tests/AccountCapacityLedgerTests.fs:93-220` is deliberately a disposable `LedgerStore.putRecord` model, not the production `ReserveProjectLaunchDemand` / `AbortUnboundProjectAdmission` / `TerminalizeLaunch` state machine. The production adapter must verify current canonical launch state, original project admission operation, immutable terminal origin, generation and one-shot side-effect reconciliation before returning proof. A mere missing admission receipt remains insufficient.
2. **Do not conflate the two operation identities.** The fixture uses the same `admission` UUID for global `reserve` and project `putRecord` (`AccountCapacityLedgerTests.fs:103-110, 475-477`). The real protocol can use a distinct global reservation operation ID and project admission operation ID. Production WQ-02 integration must independently reconcile both and test their independent replay/abort race; the fixture does not certify that mapping.
3. **Migration and invocation gates remain external.** `AccountCapacityLedger.reserve` is intentionally an inert primitive, not an activated Scheduler entrypoint. Do not wire launch or release until approved WQ-01/WQ-02 contracts, project Prepared(epoch), account Activated(epoch), capability negotiation and explicit operator rollout gates are independently accepted (accepted work-queues specification §§7-8).
4. **Account branch writer trust is an operational precondition.** `readState` validates identity/token shape and trusted ancestry; it does not rebuild every state transition from all operation receipts. Out-of-band descendant modifications of `state.json` by another trusted-push-capable writer therefore are not fully excluded by read-time structure checks alone. Enforce remote writer policy and consider a transition-provenance regression before production rollout (foundation doc lines 107-110).

No source edits, deployment, or integration are authorized by this review. These are explicit prerequisites/risks for subsequent production binding, not defects in the submitted F01/F02 corrections.
