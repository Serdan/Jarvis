## Positive findings

1. **Enrollment is separated from execution.** `Client/Modules/SourceEffectJournal.fs:300-403` provides `provisionTrustedHostRoot root anchorPath` for explicit first enrollment, guarded against either pre-existing or partially enrolled marker/SQLite file. It persists a new journal UUID/root in an independent anchor first (file `Flush(true)`, directory fsync on Linux/macOS), then creates SQLite schema including `journal_identity`. The operational `openAtHostRoot` calls only `openExistingAtHostRoot` with a fixed host-local anchor path. Neither dispatch nor retries invoke enrollment. The former `ReadWriteCreate` path in operational `openAtHostRoot` is gone; `connect` uses SQLite `ReadWrite` and missing DB fails closed.
2. **Continuity is independently checked before dispatch.** `SourceEffectJournal.fs:198-278,405-417,438-469` reads a fixed-version anchor including journal UUID, canonical root and immutable `(original UUID, operation fingerprint)` inventory. Every SQLite serializable transaction checks identity and complete inventory before and after work; new operations append/fsync anchor inventory before SQLite commits Prepared. Partial commit/crash can strand an extra anchor row but then denies all further activity instead of minting a new replay domain. Identity or inventory mismatch, schema corruption, journal deletion or root switch returns `RecoveryBlocked` before any file-handler callback.
3. **Replay and scope changes are denied.** `SourceEffectJournal.fs:438-469,633-672` only invokes the awaited file callback after durable `FirstDispatch`. `AlreadyRecorded` never redispatches, including when the recorded effect is Terminal or Uncertain. Reuse of the same UUID with a different scope, ledger epoch, source checkout, route type or request fingerprint is rejected. The pre-existing sticky scope fence and `inspectForHandoff` still report `RecoveryBlocked` regardless of terminal rows.
4. **Route gate remains deliberately nonproduction.** `Client/SignalR/Client.fs:925-970` requires the exact environment value `JARVIS_WQ03_NONPRODUCTION_HOST_BOUND_FILE=host-bound-file-v1` for caller UUID dispatch, and denies opt-in unbound legacy generation source routes. `Client/Modules/SourceEffectHostBinding.fs:109-146` independently reloads approved ledger binding, canonical source state and the journal before binding the file route. The change does not enable YieldSource or general source-mutation route coverage.

- `two_clients_reject_sqlite_rollback_to_pre_uuid_snapshot`: an otherwise-valid SQLite snapshot with same journal UUID/root but no U cannot be substituted after U is anchored; two logical clients concurrently attempting U cannot execute another effect.

- Existing intact-database replay and altered original UUID/scope tests remain in `SourceEffectJournalTests.fs`, `SourceEffectRouteBridgeTests.fs` and `SourceEffectHostBindingTests.fs`. Multiple store handles simulate two clients; test fixtures do not claim a literal OS-process restart.

## Deliberately NOT accepted / residual boundaries

- The anchor is host-local, not an external immutable trust service: a privileged operator able to destroy or replace **both** anchor and DB can re-enroll; independent trusted initial enrollment, anchor parent control and retention remain prerequisites. This is not authenticated proof against arbitrary same-OS-account mutation and must not be treated as a cross-host/cross-ledger authority.
- The upstream original source-UUID issuer, caller/session-to-registered-launch admission and account/role authority are unproven. The existing binder selects a canonical claimed checkout, but does not authenticate the caller's ownership of that launch. Therefore this code cannot grant agent source succession.
- Detached subprocesses, jobs, Git pushes/merges/retries, out-of-band/legacy mutation routes, late original remote effects, and the Git host's create-only/non-delete/retention policy for `jarvis-wip/**` remain uncovered or operator-unverified. Neither SourceEffect terminal rows nor a clean checkout can release source, work, claim, launch, token or Scheduler capacity.
- No full live host crash or separately executed two-OS-process fixture was run in this audit; tests use independent handles and fault-injected durable filesystem states. The directly inspected open-only and per-transaction checks support this **narrow inert** verdict, not positive production safety.
