## Canonical operation, receipt and head provenance
1. `read` starts by fetching its configured, trusted canonical Git binding. It rejects the asserted head or global `NextSequence - 1` mismatch and refuses missing/invalid original UUID/request digest. The assertions are not used as permission flags or independent event counters.
2. `LedgerStore.getOperationAt` resolves the original UUID under `ops/<prefix>/<uuid>.json` and verifies canonical request and original result SHA-256 digests. `getOperationOriginAt` follows the first-parent addition, rejects a modified operation blob, and checks originating commit operation UUID/request-hash trailers. `verifiedHistoricalSnapshot` requires the origin to be an ancestor of the trusted head.
3. The adapter validates original request project/actor/kind/UUID, original result UUID/kind/sequence, ordered unique receipt paths, and **all** receipt change hashes at the originating tree, not solely the requested event. The selected typed event path must be an actual member of that original change set. Any missing/mismatched entity is an error.
4. A second trusted fetch before returning rejects intervening canonical-head movement. This is a read-side freshness check, **not** atomic authorization across repositories. No caller-defined name, prefix, standalone boolean, synthetic event index or equal asserted source/project count can bypass the receipt membership check.

## Typed source-event proof
- **Task transition:** binds original task ID, attempt, action/kind, generation, actor, UUID and global operation sequence, cross-checks task record at the origin and refuses alteration of the immutable lifecycle event path. The tests exercise a real task closure, renamed task/UUID/hash/head/high-water and a rewritten immutable event.
- **Review:** requires `DecideBranchReview`, `Accepted`, matching decision sequence, reviewer actor, review ID/task, exact managed review ref/source version/decision version, reviewed source SHA and target. The current record must preserve decision identity and accepted state; Unclaimed review, changed SHA/ref/task/version/target fail. Advancing the separate source Git branch does not grant source authorization.
- **Challenge/operator:** requires original immutable challenge event path/sequence/actor/action plus task/challenge linkage. An operator response is recorded as a source event, not automatically promoted to accepted operator authority.
- **Integration:** differentiates `SubmitIntegration/Pending` from `CompleteIntegration/Integrated`, validates exact submission and accepted-review linkage, SHA, managed review/integration refs and target, and checks current terminal status. `ReviewWorkflow.completeIntegration` already rejects unreviewed merge commits: managed completion requires the exact submitted/reviewed commit. A Pending submission cannot be renamed Integrated. The new focused fixture directly tests Pending and mismatched identities, **not** an actual successful CompleteIntegration event.
- **Role:** binds `AttachRole`, original agent config version/update sequence, attached role ID and pinned role-definition version; resolves matching role membership at the same snapshot and rejects role version drift. Role membership is a routing/scope fact, **not** permission.
