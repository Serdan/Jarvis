# F01 — P1 — Direct Windows testhost can trust a non-disposable operator-profile root

**Source:** `Client.Tests/HermeticHarnessTests.fs` (global `HermeticClientTestEnvironment.BeforeAll`, around lines 126–230), versus `scripts/test-client-hermetic.fsx` (`validateScratchParent`, around lines 36–94). **Frozen SHA:** `8bfa5d7248df94755860fbdb3f73ffc03e20359b`.

**Finding.** The FSI harness correctly refuses Windows without `--scratch-parent`, rejects linked ancestors, and rejects a supplied scratch parent that is inside the *real* Windows `UserProfile` / `ApplicationData` / `LocalApplicationData`. But the NUnit assembly can also be launched directly through `dotnet vstest`. Its global fixture only requires `JARVIS_CLIENT_TEST_HERMETIC_ROOT` to be nonempty; it then calls `Path.GetFullPath` and validates containment **relative to that same untrusted root**. It does not independently establish that this root is disposable or outside the actual Windows user profile. Windows `AssertOwnerOnly` is a no-op. If a caller points the variable and associated HOME/APPDATA/LOCALAPPDATA/TEMP layout at a pre-created directory inside the operator's profile, the fixture's lexical/reparse checks are self-consistent and do not reject the profile location. It can then install the test known-folder override and run tests that create config, identity, Git data and temp files there. The ordinary direct run without a root does fail; the bug concerns an externally supplied, unsafe root.

**Why this blocks acceptance.** The task requires fail-closed operator-profile isolation regardless of invocation path. Isolation cannot depend solely on the safety checks in the optional wrapper, because the test assembly has an independently callable entry point.

**Required correction.** Before installing any overrides or invoking Client persistence code, independently verify on Windows that an externally provided root is under an explicitly attested disposable parent outside actual OS known-folder profile paths (or require a genuinely disposable Windows user/profile with equivalent defensible attestation); reject profile roots and unsafe/reparse ancestors without touching them. Add a deterministic Windows negative test for a forged but internally consistent testhost mapping that targets an unsafe root, using only synthetic or ephemeral CI profile fixtures; confirm rejection precedes test writes. Preserve direct-run refusal without a root, existing containment/junction checks, and synthetic Git-identity isolation. Do not test against any real operator profile.

**Disposition:** ChangesRequested (P1).
