## Smallest correction to consider after lease handoff

Preserve the public task+sequence contract, response snapshot and error mapping. After validation and a single verified fetch, read/validate the exact task (independent of its current pointer). Introduce a narrowly scoped internal pinned lookup for candidate checkpoint paths beneath that task's attempts subtree, using the existing Git tree/path infrastructure rather than scanning all project records or all operation UUIDs. LedgerStore.listAt at 1605–1620 presently does **not** accept this subtree; add precisely the validated task-scoped prefix, or an equivalently narrow helper if performance/ownership review requires it. Use one pinned Git tree walk over that task's attempt records, exact anchored path grammar and numeric sequence suffix; avoid per-attempt subprocesses and recursive scans of other tasks. Complexity is O(paths beneath one task), then constant number of entity reads; measure on long history and distinguish any output-limit failure from an absent checkpoint. No new persisted index, migration or global query framework in this correction. A future index is justified only by measured need.

Zero exact matching paths: normal missing-record failure (not no active attempt). More than one matching path: integrity failure; never pick arbitrarily. For the unique candidate, use existing required/decodeEntity/readAt at the same snapshot (ReviewWorkflow 793–829; LedgerStore 1593–1603). Check record TaskId, AttemptId and Sequence exactly against the request and parsed path, validate the historical attempt entity and matching identity, and validate checkpoint historical assignment generation/owner against its immutable assignment issue where required. Do not compare to the *current* owner or current generation (transfer/reissue can legitimately change these), or synthesize missing provenance. Existing AgentCheckpoint entity parser checks schema/member presence and kind, not all identity invariants; fail closed on malformed or mismatched content. Existing operation provenance helpers at LedgerStore 1037–1100 resolve UUID-keyed journal entries, not sequence-keyed lookups; avoid O(all project operations) reverse-search. Preserve the verified-snapshot semantics and never fetch again mid-resolution. If deeper immutability verification is required by existing ledger contract, reuse its verified lineage mechanisms rather than inventing authority.
